# 云助理 × Roomie 架构（整理后）

> 由 [[00.需求/roomie/架构初稿]] 汇总整理，结合 [[00.需求/roomie/云助理群场景提效·Roomie接入初版方案]] 的场景与能力清单。
>
> 🔗 Roomie 侧提供的开放 API 接口文档（接入用）：https://beike.feishu.cn/wiki/JFf1wFteCi4gGik4io0crh15nRm

## 1. 总体架构

```
┌─────────────────────────────────────────────────────────┐
│                     数据来源（三条路径）                    │
│  ① 群聊消息全量数据        ② 群内 Excel 表格        ③ 现有系统  │
│  （定时拉取+标记 → 落库）   （每日定时抓取 → 落库）    （项目信息） │
└───────────────┬─────────────────────────────────────────┘
                ▼
┌─────────────────────────────────────────────────────────┐
│                     数据基础（落库后）                      │
│  消息数据 + 进展数据（入库/送货等）+ 项目信息                 │
└───────────────┬─────────────────────────────────────────┘
                ▼
┌─────────────────────────────────────────────────────────┐
│                清洗分析（定时任务，逐消息+上下文）              │
│  归类问题类型 · 判断是否需要云助理处理                          │
└───────────────┬─────────────────────────────────────────┘
                ▼
┌─────────────────────────────────────────────────────────┐
│                分析汇总 → 为云助理提供能力                    │
│  查询 · 回答 · 外呼 · 转发@ · 操作 · 通知                    │
└─────────────────────────────────────────────────────────┘
```

## 2. 数据基础（三条数据来源路径）

| # | 来源 | 内容 | 获取方式 |
|---|---|---|---|
| ① | **群聊消息全量数据** | 群内所有消息（问题、答复、流转） | **定时任务 + 标记**拉取后落库；之后另一个定时任务对每条消息**结合上下文**做清洗分析：归类问题类型、判断是否需要云助理处理 |
| ② | **群内进展数据（Excel 表）** | 材料入库、送货等 Excel 表（排线表、入库表等） | **每日定时抓取任务**后数据存储 |
| ③ | **现有系统功能** | 对应项目的信息 | 通过现有功能拉取，是数据来源的一部分 |

> 三路数据落库后构成数据基础，其上做分析汇总，为云助理提供能力。

## 3. 目前主要解决的 5 类问题

| # | 问题类型 | 说明 |
|---|---|---|
| 1 | **主材问题整改** | 供应商责任类问题（整改、谁负责），需供应商给结论 |
| 2 | **送装预约与调整** | 改约、甲醛不做了取消订单等 |
| 3 | **业务办理与信息核实** | 各类办理事项与信息核实 |
| 4 | **定制柜进度咨询** | 台账/系统可查，可直接回答 |
| 5 | **主材进度确认** | 系统无安装时间数据，需找到供应商要结论 |

> 对应 [[00.需求/roomie/云助理群场景提效·Roomie接入初版方案]] §2 的四类问题拆分：进度收集后回答（4、5 台账可查部分）、找到供应商给结论（1、5 系统无数据部分）、数据汇总（数据基础②）、送装预约与调整（2）。新增第 3 类「业务办理与信息核实」为架构初稿新增口径。

## 4. 能力清单（针对上述问题提供的能力）

| # | 能力 | 具体动作 | 支撑的问题类型 |
|---|---|---|---|
| 1 | **查询项目详细信息、回答问题** | 回答「业主什么时候送货？什么时候安装？」等咨询 | 定制柜进度咨询、主材进度确认（台账可查部分）、业务办理与信息核实 |
| 2 | **拿到供应商电话进行外呼** | 供应商超时不回时打电话催 | 主材问题整改、主材进度确认（系统无数据部分） |
| 3 | **转发问题到特定群聊，并 @ 特定的人** | 识别问题归属 → 转发对应供应商群 @ 对接人 | 主材问题整改、主材进度确认（需供应商给结论） |
| 4 | **进行操作**（送装预约、复尺任务通知等） | 执行预约调整、通知类操作 | 送装预约与调整、业务办理与信息核实 |
| 5 | **供应商计划与排期查询 + 通知/回答** | 从基础数据拿到供应商的计划和排期 → 通知供应商在特定时间内完成任务 / 回答业主关于供应商什么时间送货的问题 | 主材进度确认、数据汇总场景 |
| 6 | **便捷的接口** | 为以上功能提供一个统一便捷的接口 | 全部 |

## 5. 与 Roomie 接入方案的对应

> 初版方案 §3 已改为**以功能点为维度**撰写（要实现什么功能 → 具体实现方式，优先封装现有能力）。

| 架构初稿能力 | Roomie 接入方案（初版方案 §3 功能点） | 落地方式 |
|---|---|---|
| 数据基础①（消息清洗） | 3.1 群消息问题归类汇总 | 消息上下文获取 + LLM 归类 + 以人为维度集中展示 + 双向待办提醒 |
| 数据基础②（Excel 落库） | 3.2 材料送货进展数据汇总 | 小工具逻辑照搬迁移：机器人抓取落库 + 汇总推送 + 侧边栏实时查询 |
| 转发 @ | 3.3 消息转发 | 归属路由 + LLM 文案 → 一键转发（半自动默认）/自动转发（企微群迁移后） |
| 外呼 | 3.4 供应商外呼 | 人工触发、系统承接通话，记录留档 |
| 查询回答 | 3.5 项目信息聚合查询 | 封装主材订单考核/送货/供应链现有接口 → 汇总展示（单页面查全）+ Agent/Skill 自动回复 + 侧边栏一站式查询 |
| 操作 | 3.6 业务操作（只给入口） | 只读查询 + 鲁班深链预填，复用现有能力 |
| 供应商计划排期 | 3.5 聚合查询 + 3.2 材料送货进展 | 排线/入库落库数据 + 项目详情供应商视角 |

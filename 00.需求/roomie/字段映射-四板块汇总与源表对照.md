# 字段映射：四板块汇总 ↔ 源表对照

>
> 口径来源：三张 kdocs sheet 表头为 **2026-11-12 实测**（原始 xlsx 直接解析，列号+列名逐一核对）；排线表无真实样例，按总方案 7.2 草案映射（标注【假设】）。展示列清单受原始 JS 缺失限制（5 份文件未补投），已映射部分以「需求文档口径 + 实测表头」为准，完整展示列清单仍是技术方案 TODO ④。

## 2、明日送货（tomorrow_delivery）← 排线表

**源**：排线表（排线表群每日 18–19 点发的 Excel，唯一人工输入，`DispatchSourceProvider` 入口接入）。

**口径（代码可依，出自同业务查询侧建模稿 `Documents/Codex/2026-11-06/xia-ni/outputs/`——dashboard_queries.sql + 材料入库与送货数据库设计.md，按同一张推送截图反推）**：

| 口径 | 代码依据 |
|-|-|
| 行粒度 = **一条送货明细**（一次送货安排中一个订单/批次的材料范围），非一个项目一行 | dashboard_queries.sql 明日送货段（`delivery_item` 粒度） |
| 「明日」判定 = 计划送货日为业务今天 +1（北京时间自然日） | `SET @tomorrow = DATE_ADD(@business_today, INTERVAL 1 DAY)` + `planned_delivery_date = @tomorrow` |

| 收货人/电话/地址 = 送货单级快照（不取订单主数据，保历史单据不被主数据修改污染） | delivery_order `receiver_*` 快照列 |

## 6.5、推送文本渲染（ExcelPushTextRenderer，一键推送链路中间层）

一键链路：`POST /api/v1/open/excel-push/push` → analyze（读 clean 文件出三板块）→ 渲染 → `RoomiePushService.pushToGroups`（现成 roomie 通道，目标群/机器人走 `roomie.push.*` 配置）。

| 渲染规则 | 说明 |
|-|-|
| 一板块一条消息，三条连发 | 单条长度安全；连发间隔由 `roomie.push.send-interval-ms`（200ms）控 QPS |
| 行格式 | 每板块明细行前带列名表头 `日期语义 | 供应商 | 品类 | 业主 | 工长 [| 工程经理]`（已确认口径：**不带项目单号和状态**）；明细行 `· yyyy-MM-dd 供应商/品牌 品类 业主 工长 [工程经理]`。业主：在库未送取 `E 姓名`、正单取 `AA 业主姓名`；工长：在库未送取 `N 工长姓名`；工程经理：在库未送取 `O 工程经理`、正单取 `H 工程经理`。**反补板块不带工程经理列**（工程经理本期不回查——已确认口径） |
| 反补人员补齐 | 反补源表无业主/工长列，analyze 内 `enrichReworkPersons` 调订单 API `AssistantProjectOrderService#batchQueryAssistantProjectOrderList`（经 `ProjectOrderManager.batchQueryProjectOrderList`，18 位项目单号即 projectOrderId，无用户上下文 ucid 传 null）一次批查带回 homeownerName/foremanName。工程经理 API 里有（`projectServerBaseInfos` 的 `butler_manager` 项）但本期不取。API 失败不阻断分析（log 后跳过，业主/工长显示 -） |
| ⚠️ AA 列陷阱 | 反补 sheet AA 列公式 `VLOOKUP(项目单号, 云助理订单!A:B, 2, 0)` 取的是「云助理」跟进人（黄佳丽 287 / 罗泽丹 150，438 行映射表）——**不是业主**，勿映射进 customerName；业主走订单 API 回查 |
| 日期格式 | 全部统一 `yyyy-MM-dd`（行前缀日期、日报标题时间戳同格式；空日期显示 `----------` 占位防列塌） |
| 日报标题 | 首条消息头部：`【衣柜到货进度日报】yyyy-MM-dd HH:mm` + 三板块总条数（随首板块一起发） |
| 日期前缀语义 | 反补=预计到工地 / 在库=到库 / 正单=预计入库，消息尾行注明语义 |
| 空板块 | 仍发「0条」标题行——群里看不到板块即「没有相关单」的语义 |

## 6、板块间规则列

**跨板块字段（不在单表内，由解析引擎在板块间计算）**：

| 规则 | 依赖字段 | 实现位置 |
|-|-|-|
| 去重：出现在「明日送货」→「在库未送」不再提醒 | 明日送货板块的 project_id 集合（排线表【假设】`project_id` 列）× 在库未送板块 `C 项目单号` | `SectionAssembler`（过滤在命中名单的 stock_unsent 行，不落库） |

| 批次标识 batch_id | 非源表字段：解析时刻 `yyyyMMddHHmmss` | 引擎生成，贯穿落库/查询/微调 |
| 业务日期 biz_date | 非源表字段：上传日 +1（明日送货日） | 引擎生成 |

**落库对照**（与 [[eden-agenda-Excel推送链路迁移-技术方案]] 4.1 数据模型对应）：上表「汇总结果字段」中带括号标注的 4 个字段即窄表冗余列（project_id / district / supplier / plan_date）的**取数来源**；其余字段进 `cells_json`（投影展示列）+ `headers_json`（展示表头）。

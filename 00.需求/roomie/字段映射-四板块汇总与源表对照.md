>
> 口径来源：三张 kdocs sheet 表头为 **2026-11-12 实测**（原始 xlsx 直接解析，列号+列名逐一核对）；排线表无真实样例，按总方案 7.2 草案映射（标注【假设】）。展示列清单受原始 JS 缺失限制（5 份文件未补投），已映射部分以「需求文档口径 + 实测表头」为准，完整展示列清单仍是技术方案 TODO ④。

## 2、明日送货（tomorrow_delivery）← 排线表

**源**：排线表（排线表群每日 18–19 点发的 Excel，唯一人工输入，`DispatchSourceProvider` 入口接入）。

**口径（代码可依，出自同业务查询侧建模稿 `Documents/Codex/2026-11-06/xia-ni/outputs/`——dashboard_queries.sql + 材料入库与送货数据库设计.md，按同一张推送截图反推）**：

| 口径 | 代码依据 |
|-|-|
| 行粒度 = **一条送货明细**（一次送货安排中一个订单/批次的材料范围），非一个项目一行 | dashboard_queries.sql 明日送货段（`delivery_item` 粒度） |
| 「明日」判定 = 计划送货日为业务今天 +1（北京时间自然日） | `SET @tomorrow = DATE_ADD(@business_today, INTERVAL 1 DAY)` + `planned_delivery_date = @tomorrow` |
| 送货日期语义 = **计划发车日**；若排线表头实际指到场日，映射到「预计到工地日」，两种时间不合并为一列 | 设计稿 3.3 送货单声明 |
| 明日送货与反补预计到工地**可同条并存**（两板块查询条件交集，非重复数据） | 设计稿 §4 末段 |
| 收货人/电话/地址 = 送货单级快照（不取订单主数据，保历史单据不被主数据修改污染） | delivery_order `receiver_*` 快照列 |

排线表**无真实样例、原始 MOMA 小工具 JS 亦未找到**（全盘检索无 `push-full-chain.js` 等文件）——下表**列级映射**按总方案 7.2 草案标注【假设】，样例或原始 JS 到手后逐列校正：

| 品牌/供应商（supplier 冗余列） | `supplier_id` 供应商/品牌 | |

## 6、板块间规则列

**跨板块字段（不在单表内，由解析引擎在板块间计算）**：

| 规则 | 依赖字段 | 实现位置 |
|-|-|-|
| 去重：出现在「明日送货」→「在库未送」不再提醒 | 明日送货板块的 project_id 集合（排线表【假设】`project_id` 列）× 在库未送板块 `C 项目单号` | `SectionAssembler`（过滤在命中名单的 stock_unsent 行，不落库） |
| 板块标题分组：赵公口 / 永外…大区 | district 冗余列：在库未送 `L 订单大部`、正单 `F 订单大部`、排线表大区列（待样例核对） | 展示侧按 district 分组渲染（推送截图口径） |
| 批次标识 batch_id | 非源表字段：解析时刻 `yyyyMMddHHmmss` | 引擎生成，贯穿落库/查询/微调 |
| 业务日期 biz_date | 非源表字段：上传日 +1（明日送货日） | 引擎生成 |

**落库对照**（与 [[eden-agenda-Excel推送链路迁移-技术方案]] 4.1 数据模型对应）：上表「汇总结果字段」中带括号标注的 4 个字段即窄表冗余列（project_id / district / supplier / plan_date）的**取数来源**；其余字段进 `cells_json`（投影展示列）+ `headers_json`（展示表头）。

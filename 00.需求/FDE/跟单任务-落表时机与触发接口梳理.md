### 2.1 五个触发场景：上游接口 → 发布点

| 场景 | triggerScene | 上游触发接口/消息 | 业务处理链 | 发布点 |
|---|---|---|---|---|

### 2.2 延迟合并机制（事件 → 队列 → 消费）

```
发布点 publishEvent
   │
   ▼
FollowUpRecalculateEventListener（@Async("pushTaskToQueueExecutor") + @EventListener）
   ├─ inScope 过滤（范围表无此订单 → 不入队）
   ├─ 订单级 Redisson 锁 construction:follow_up:recalculate_enqueue_lock:{orderId}
   ├─ 幂等：该订单已有 WAIT 记录 → 跳过（10 分钟窗口内多事件合并为一次重算）
   └─ insert follow_up_recalculate_queue(status=WAIT)；异常仅告警，由 ScanTask 兜底
   │
   ▼
FollowUpQueueConsumeTask（LianjiaSchedule key=follow-up-queue-consume-task）
   ├─ selectByStatus(WAIT) 逐单 recalculate
   ├─ 成功 → status=DONE；失败 → status=FAIL + retry_count+1（⚠️ FAIL 不会被再次捞起，仅靠 ScanTask 兜底）
   │
   ▼
FollowUpEngineServiceImpl.recalculate(projectOrderId)
   ├─ inScope + 订单状态窗口过滤（>301 且 ≤310 或 ≠竣工）
   ├─ 状态流转 diff（完成/取消/successor_finished=1→已完成）
   ├─ 尾款任务考核时间同步（基装验收 实际>预测>考核）
   ├─ 候选过滤（安装流程+非终态+未打标+有考核时间+Apollo 品类/taskType 命中）
   ├─ 前置依赖校验（本地关系表 STANDARD_RELATION，直接前置全部终态才通过）
   ├─ 距考核 ≤warnDays 创建（预警）/ ≤0 升延期（只升不降）
   └─ 尾部一次批量 ES 双写（失败仅告警，MySQL 为准）
```

## 三、能实现的具体功能

### 3.1 任务自动生成（无人工介入）

- **D 类材料催办**：对范围内订单，按 Apollo 配置的品类→taskType 规则（`follow.up.task.generate.rule`），在任务链路"当前应执行节点"（直接前置全部完成）距考核 ≤3 自然日时自动建任务（预警黄），考核当天自动升延期红；排程任务完成/取消自动流转终态；后置任务已完成的节点自动跳过（successor_finished 打标）。
- **催尾款**：瓦工作业验收完成且尾款未收齐自动建任务；基装验收完成自动升延期；尾款收齐消息自动置完成。考核时间自动跟随基装验收（实际>预测>考核）刷新。
- **催返补下单/接单**：装中返补货单被拒单且无在途单自动建催下单；供应商二次下单完成自动结掉催下单并接力建催接单；接单自动完成；货单取消自动取消。
- **整单收口**：项目竣工→全部在途任务已完成；取消/解约→全部已取消，且订单自动移出跟单范围。
- **存量初始化**：上线时按订单当前状态批量补建尾款/返补任务（后门）。

### 3.2 任务跟进处理（云助理作业台）

- **写跟进**（handle operateType=FOLLOW）：填跟进内容（≤500 字）→ 任务待跟进→跟进中（不可逆），落流水。
- **约下次跟进**（NEXT_FOLLOW）：记下次跟进时间流水，任务状态不变，列表可按下次跟进时间区间筛选。
- **手动关闭**（CLOSE）：填关闭原因 → 无需跟进（终态），且该节点**不再自动重建**（去重包含无需跟进）。
- **跟进记录查询**（task/records）：按任务倒序返回全部操作流水（类型/内容/下次跟进时间/关闭原因/操作人/时间）。

### 3.3 查询与展示

- **精确筛选分页**（task/page，MySQL）：任务类型、状态、风险等级、品类、供应商、订单 id。
- **作业台主查询**（task/search，ES）：额外支持跟进人 ucid、作业大区、下次跟进时间区间、货单号、自定义排序；ES 出 id 回 MySQL 拼详情。
- **模糊搜索**（task/order/search）：订单号/小区/业主/服务者模糊搜（销售项目 ES，默认分公司=Apollo `follow.up.task.branchOfficeCode`、默认状态 302~310），与跟单范围取交集，截断 100 条回传。
- **列表信息聚合**：每条任务自动挂业主姓名、服务者列表、物业地址、订单阶段、处理人姓名（按 handlerRole 匹配服务者）、最近/下次跟进时间（流水聚合）、尾款任务挂瓦工作业实际完成时间。
- **筛选项字典**：task/materials（配置的品类，名称匹配 029 履约类目）、task/companies（分公司）、task/project-statuses（项目状态）。

### 3.4 范围与分配（一期）

- **范围同步**：moma 定时读在线文档 → `scope/sync`（纯订单 id 覆盖写）或 `scope/sync-v2`（随单带作业大区）；`scope/increment` 增量加/删；`scope/list` 查询。所有生成/流转链路 inScope 校验，范围外不跑。
- **跟进人分配**：`region-relation/insert` 维护"作业大区→跟进人"（一大区一人），任务创建时自动快照大区+跟进人 4 字段；支持按订单批量回填（handler-backfill）。

### 3.5 运维能力（后门接口 `/api/construction/follow-up/backdoor/*`）

| 接口 | 功能 |
|---|---|
| refresh-finish-mark | 刷范围内订单的 successor_finished 完成标记（空参=全范围） |
| recalculate | 指定订单立即触发 D 类重算 |
| init-final-payment-task / init-replenish-task | 存量补建尾款/返补任务，返回逐单结果 |
| assessment-time-backfill | 按基装验收时间补任务考核时间（含终态） |
| delete-wait-follow-task | 删除待跟进任务（仅该状态可删） |
| update-successor-finished | 按排程任务 id 批改打标（0/1） |
| mark-recheck-finished | 订单+品类维度：下单全完成时给复尺/通知复尺打标 |
| es-sync | 按订单全量重推 ES（修复查询副本） |
| handler-backfill | 补任务跟进人 4 字段 |

### 3.6 当前不具备 / 待补的能力

- **无 Apollo 总开关**（方案中 enabled/scopeEnabled/materialUrge.enabled 未实现）：无法一键停跑，止血只能清空范围表。
- **队列 FAIL 无重试**：失败记录不会被再次消费，仅靠 ScanTask 兜底收敛。
- **返补"完成+串行创建"无事务**：极端情况留下中间态，需后门 init 修复。
- **ES 双写失败不重试**：search 结果可能短暂缺失，依赖 es-sync 修复；handler-backfill 的 ES 推送被注释，回填后按跟进人筛选查不到。
- **next_follow_up_time 不在任务表**：仅存在于流水与 ES，MySQL 侧无法直接按下次跟进时间查询任务表。

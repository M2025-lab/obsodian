## 二、前置条件

1. **建表**：执行 `doc/material_notify_execute_record_ddl.sql`（CREATE TABLE 已含全部默认值；文件内 4 段历史 ALTER 针对旧表，新库直接建表可跳过）。
2. **Apollo**：
   - 开关 A `notification.remeasure.automation.open`：`projectManagers` 含 `3000110000021901`；
   - 开关 B `notification.remeasure.automation.autoNotify`：包含 P1、P2 两个品类——doRecord 步骤 5 按此白名单拦截，**漏配则全部不落记录**。
3. **测试数据**：订单 `757348472546951168` 下准备通知复尺任务（task_dispatch + 通知节点 nodeType=20 + 复尺执行节点），node `executor_id=3000110000021901`、`process_code` 非空；P1 品类的识别结果经 `POST /api/recognize/task/result` 写入 automation 表（judge_result=1 可通知，带推荐图片/推荐上门时间），P2 品类**不写**识别结果。
4. **服务**：本地起 edar-starlord；HTTP 头带 `X-KE-UCID: 3000110000021901`。
5. 记录为**异步落库**（handleNode 返回后线程池执行），断言前等待 1-2s 或轮询日志 `recordAfterHandle insert`。

|---|---|---|
| 1 | 前置 1-4 | 记录表该订单范围为空 |

## 四、用例矩阵

### A 组：提交记录（record_type=1）

| # | 前置 | 步骤 | 预期 |
|---|---|---|---|
| A1 手动提交 | P1 品类通知节点（识别结果 judge=1） | `POST /material-task/dispatch/handle`，qualified=1，nodeType=20 节点 | 落 1 条：record_type=1，notify_execute_type=**3**，operator_id/name=提交人（3000110000021901），event_time=节点 submit_time，gb_code=任务城市码，recognized=1，judge_result=1，recognize_applied=1 |
| A2 一键通知 | P1 品类另一任务，节点未填图/时间，automation 有推荐值 | `POST /api/material/notify/task/batch/handle`（嵌套 taskDispatchNodeItems） | notify_execute_type=**1**；ai_adoption_type 按提交值 vs 推荐值比对（一键透传推荐值→1 采纳） |
| A3 自动通知 | P1 品类，judge=1 且 automation notify_execute_type=0 | `POST /api/material/notify/task/auto/execute`（无 body） | notify_execute_type=**2**；ai_adoption_type=**1**（自动链路提交值即识别表推荐值）；automation 表该行 notify_execute_type 同步写 2（一期既有行为，顺带回归） |
| A4 无识别记录提交 | **P2 品类**（automation 无该品类记录） | 同 A1 | recognized=**0**，judge_result=**0**（NULL→列默认），recognize_applied=0，ai_adoption_type=**0** |
| A5 小师傅端合格提交 | 复尺执行节点（nodeType≠20）qualified=1 | MaterialMeasureTaskController handle 入口提交 | **不落记录**，日志 `node type is not notify can start`（6b 拦截） |

### B 组：驳回记录（record_type=2）

| # | 前置 | 步骤 | 预期 |
|---|---|---|---|
| B1 驳回归因-自动 | A3 已落提交记录（execute_type=2），任务 restart 产生复尺执行节点 | `POST /material-task/dispatch/handle`，qualified=2 | 落 record_type=2：notify_execute_type=**2**（抄上一轮提交），node_id=**本次 qualified=2 提交的节点**，operator=本次驳回人；recognized/judge_result=驳回时刻识别表快照 |
| B2 驳回归因-手动 | 上一轮为 A1（execute_type=3） | 同上 | 驳回记录 notify_execute_type=**3** |
| B3 驳回归因-存量 0 桶 | 任务无提交记录（新任务直接走驳回，或先清掉该 task_dispatch 的提交记录） | 同上 | notify_execute_type=**0**（未查到上一轮），其余快照正常 |
| B4 小师傅端驳回 | 复尺执行节点 | MaterialMeasureTaskController handle，qualified=2 | **落驳回记录**（驳回分支不限 nodeType）；SDM 挂起消息照常发（异步 CompletableFuture，一期行为） |
| B5 多轮驳回 | 同 task_dispatch 驳回→restart→再提交→再驳回 | 两轮完整流程 | 4 条记录：2 提交 + 2 驳回（各轮 node_id 不同不冲突）；第二轮驳回归因=第二轮提交的执行方式 |

### F 组：指标查询接口

统一约定：`POST`，`Content-Type: application/json`；时间传字符串 `yyyy-MM-dd HH:mm:ss`（@JsonFormat GMT+8）；成功 `code=2000`。过滤示例用品类 P1 的实际 material_code。

```bash
BASE=http://localhost:8080
# 汇总
curl -s -X POST "$BASE/backdoor/notifyRecord/statSummary" -H 'Content-Type: application/json' \
  -d '{"startTime":"2026-10-01 00:00:00","endTime":"2026-10-26 23:59:59","materialCode":"<P1品类code>"}'
# 趋势
curl -s -X POST "$BASE/backdoor/notifyRecord/statTrend" -H 'Content-Type: application/json' \
  -d '{"startTime":"2026-10-01 00:00:00","endTime":"2026-10-26 23:59:59"}'
# 明细分页
curl -s -X POST "$BASE/backdoor/notifyRecord/page" -H 'Content-Type: application/json' \
  -d '{"startTime":"2026-10-01 00:00:00","endTime":"2026-10-26 23:59:59","recordType":2,"pageNum":1,"pageSize":10}'
```

| # | 用例 | 预期 |
|---|---|---|
| F1 | statSummary 全量（仅时间） | data 四计数 = 校验 SQL §五-2 手工聚合：submitCount / submitRecognizedCount / rejectCount / rejectRecognizedCount |
| F2 | statSummary 缺 startTime 或 endTime | fail：message=`startTime/endTime必填（yyyy-MM-dd HH:mm:ss）`，code≠2000（statTrend/page 同） |
| F3 | statSummary 带过滤 materialCode/gbCode/notifyExecuteType/judgeResult | 各过滤生效且可组合；空串视为不传 |
| F4 | statTrend | 按天升序，statDate=`yyyy-MM-dd`；各天四计数之和 = F1 汇总 |
| F5 | page 默认排序 | rows 按 `event_time desc, id desc`；total=符合条件总数 |
| F6 | page 默认分页 | 不传 pageNum/pageSize → 第 1 页 20 条；pageNum=0/-1 → 按 1 处理 |
| F7 | page 上限 | pageSize=500 → 实际 200 条 |
| F8 | page 空结果 | 时间窗内无数据 → `total=0, rows=[]`（不执行列表查询） |
| F9 | page recordType 过滤 | recordType=1 仅提交 / =2 仅驳回 |
| F10 | 时间边界 | event_time 恰等于 startTime/endTime 的记录**包含**在内（>= / <=） |
| F11 | 字段回显 | rows 为 VO 出参：Date 字段序列化为 `yyyy-MM-dd HH:mm:ss` 字符串（非时间戳）；id/projectOrderId/taskDispatchId/taskDispatchNodeId 为**字符串**（防 JS Number 精度截断，如 `"757348472546951168"` 不得变成 `…100`） |

## 五、验证 SQL 与对账

```sql
-- 1. 测试订单明细全查（字段级断言用）
SELECT id, project_order_id, material_code, gb_code, task_dispatch_id, task_dispatch_node_id,
       record_type, notify_execute_type, recognized, judge_result, recognize_applied,
       ai_adoption_type, operator_id, operator_name, event_time
  FROM material_notify_execute_record
 WHERE project_order_id = 757348472546951168
 ORDER BY id;

-- 2. 四计数手工聚合（与 statSummary 对账，时间窗换成实际测试窗口）
SELECT IFNULL(SUM(record_type = 1), 0)                          AS submitCount,
       IFNULL(SUM(record_type = 1 AND recognized = 1), 0)       AS submitRecognizedCount,
       IFNULL(SUM(record_type = 2), 0)                          AS rejectCount,
       IFNULL(SUM(record_type = 2 AND recognized = 1), 0)       AS rejectRecognizedCount
  FROM material_notify_execute_record
 WHERE event_time >= '2026-10-01 00:00:00' AND event_time <= '2026-10-26 23:59:59';

-- 3. 按天聚合（与 statTrend 对账）
SELECT DATE_FORMAT(event_time, '%Y-%m-%d') d, COUNT(*) cnt
  FROM material_notify_execute_record
 WHERE project_order_id = 757348472546951168
 GROUP BY d ORDER BY d;

-- 4. 归因链核对：每条驳回记录的执行方式 = 同 task_dispatch 最近一条提交记录的值（或 0）
SELECT r.id reject_id, r.task_dispatch_id, r.notify_execute_type reject_type,
       (SELECT s.notify_execute_type FROM material_notify_execute_record s
         WHERE s.task_dispatch_id = r.task_dispatch_id AND s.record_type = 1
           AND s.event_time <= r.event_time
         ORDER BY s.event_time DESC, s.id DESC LIMIT 1) last_submit_type
  FROM material_notify_execute_record r
 WHERE r.record_type = 2 AND r.project_order_id = 757348472546951168;
-- 预期：reject_type = IFNULL(last_submit_type, 0)
```

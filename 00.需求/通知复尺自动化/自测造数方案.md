# 复尺通知自动化 · 自测造数方案（v3 · 全组合矩阵）

> 适用：edar-starlord **local profile** → 测试库
> 原则：**不新建任何数据表**（含 TEMPORARY TABLE），全部纯 INSERT；automation 表经 `/result` 接口造数；`AUTOTEST_` 前缀便于清理，文件头自带清理段可重跑。
> 三张表 DDL 见文末「附录」。

---

## 一、造数要求（本轮）

| 维度 | 取值 |
|---|---|
| project_order_id（锁定，共 3 个） | `546068027139760128`、`577257627351097344`、`499472368956997632` |
| material_code（可扩展） | `AUTOTEST_M01`、`AUTOTEST_M07`、`AUTOTEST_M11`（本轮固定用这 3 个；后续按需追加 M08/M09…） |
| task_type | `3`（复尺） |
| automation 通知类型 = judge_result | `1`（可通知）、`4`（现场已完成需关闭） |
| node 图片 images | 有、无 |
| node 期望上门时间 notice_retain_time | 有、无 |

**组合矩阵**：`judge_result(2) × node 图片(2) × node 期望上门时间(2) = 8` 用例，全部 `task_type=3`，覆盖正负全枚举。

> `project_order_id` 取真实订单号（= `order_no` = `home_order_no`，三表同值），不再自造假项目。
> `executor_id`（node 工长）= 请求头 `X-KE-UCID` = Apollo `projectManagers` = `88888888`（测试工长A），三处必须一致。

## 三、造数 SQL：清理段（文件头，可重跑）

```sql

-- ============================================================
DELETE FROM material_notify_task_automation
 WHERE judge_remark LIKE 'AUTOTEST%' AND task_type = 3;

DELETE FROM task_dispatch_node
 WHERE remarks LIKE 'AUTOTEST|%';

DELETE FROM task_dispatch
 WHERE material_code LIKE 'AUTOTEST_%' AND task_type = 3;
```

> automation 行无法直接 DELETE 清理时（经 /result 落库），同样可用此段按 `judge_remark LIKE 'AUTOTEST%'` 清理。

## 五、造数 SQL：task_dispatch_node（8 主节点，INSERT…SELECT 从 dispatch 生成）

> 主节点全 `node_type=20`、`process_status=2`、`state=1`、`executor_id=88888888`、`executor_type=3`（管家/工长）。

> `task_dispatch_node` 实际表**无 `source` 列**（model 有、DB 无），INSERT 列清单不得带 source。
> 次节点 `node_type=60` 可按需补，本期 8 用例不造次节点（handle 触发后由 getNextNodeType 自动激活）。

> `notice_retain_time` 兜底 CASE 行避免遗漏，实际由矩阵行命中。
## 六、automation 经 `/result` 接口造数（8 条，不得直插 SQL）

> automation 表不能直插：`/result` 接口内部做 `validateParams` 8 字段手写校验 + `images` 逗号拼接 + `notify_execute_type=0`/`ai_adoption_type=0` 固定落库 + `recommend_visit_time` = `recognize_time + 3d`。
> `recognize_time` = **昨天**（T+1 口径，服务按 `DATE_SUB(CURDATE(), INTERVAL 1 DAY)` 精确等值查）；`recommend_visit_time` = 今天 +3d。
> `judge_result` 按矩阵：M01/M03/M04/M06/M08 = 1，M02/M05/M07 = 4。
> `images` 列表（接口侧 List，入库前逗号拼接）每条给 1~2 个 url（即便 node 无图，automation 侧仍可带图，独立于 node images）。

## 七、Apollo 开关（先配开关，再造数）

```json
// 开关A  notification.remeasure.automation.open   —— 功能级：batch/query、summary、auto-fill、save 依赖
{ "cities": [], "projectManagers": ["88888888"], "departments": [] }

// 开关B  notification.remeasure.automation.autoNotify —— 品类级：auto/execute 按 material_code 匹配
{
  "AUTOTEST_M01": { "cities": [], "projectManagers": ["88888888"], "departments": [] },
  "AUTOTEST_M07": { "cities": [], "projectManagers": ["88888888"], "departments": [] },
  "AUTOTEST_M11": { "cities": [], "projectManagers": ["88888888"], "departments": [] }
}
```

- **语义（代码核实）**：空数组 = 该维度不参与匹配（全放开）；三数组全空/未配置 = 永不命中（fail-closed）。
- 本轮 3 个 material_code 全配开关 B → auto/execute 全部命中（验证执行不跳过）；如需验证「跳过」分支，临时移除某个品类。
- `X-KE-UCID` 三处一致：`node.executor_id`（造数 88888888）= 请求头 `X-KE-UCID` = Apollo `projectManagers`。
- `site/complete/query`（judge=4 桶）受开关 A 过滤，但**无 summary 时间窗限制**。
## 八、执行顺序与断言

| STEP | 内容 | 断言 |
|---|---|---|
| 0 | 配 Apollo 开关 A/B | — |
| 1 | 清理段 + task_dispatch(8 行) | `SELECT COUNT(*)=8 FROM task_dispatch WHERE material_code LIKE 'AUTOTEST_%' AND task_type=3` |
| 2 | task_dispatch_node(8 行 INSERT…SELECT) | `SELECT COUNT(*)=8 FROM task_dispatch_node WHERE remarks LIKE 'AUTOTEST\|%'` |
| 3 | 经 `/result` 造 automation(8 条) | `code=2000`；automation 8 行，judge=1 共 5 条、judge=4 共 3 条，`notify_execute_type=0` |
| 4 | batch/query（snake_case 入参 `task_type`/`project_order_id`） | notifyTasks：judge=1 的 M01/M03/M04/M06/M08 共 5 条；delayTasks：无（judge=2/3 才入 delay，本轮无）；judge=4 的 M02/M05/M07 **不返回** |
| 5 | site/complete/query | 返回 judge=4 的 M02/M05/M07 共 3 条（受开关 A 过滤，无时间窗限制） |
| 6 | auto-fill | M01/M02/M05/M06（node 有图有时间）→ node 优先；M03/M04/M07/M08（node 缺图或缺时间）→ automation 兜底补缺项 |
| 7 | save（Date 传字符串 `yyyy-MM-dd HH:mm:ss`） | 写 node 两列（images/notice_retain_time）；node 不存在/为空 → `ERROR_PARAM_ILLEGAL` |
| 8 | batch/handle（嵌套 `taskDispatchNodeItems`，nodeId 不得重复） | success + 幂等 already |
| 9 | auto/execute（无 body） | 命中 judge=1 + notify_execute_type=0 → executed；复测 0（CAS） |

**接口入参口径（踩坑）**：
- `batch/query` 入参 `@JsonProperty` snake_case：`task_type`、`project_order_id`（驼峰被忽略，过滤失效）。
- `save`/`handle` 的 Date 字段带 `@JsonFormat(pattern="yyyy-MM-dd HH:mm:ss", timezone="GMT+8")` → 传**字符串日期**，别用时间戳。
- `batch/handle` 入参嵌套：`NotifyBatchHandleParam{operator, taskDispatchNodeItems:[{taskDispatchNodeId, noticeRetainTime, images, ...}]}`，非扁平。

## 踩坑速记（造数相关）

1. **不建临时表**：autotest TEMPORARY TABLE 跨 session 失效 → 纯 INSERT。
2. **task_dispatch_node 无 `source` 列**（model 有、DB 无）：INSERT 列清单必须去掉。
3. **material_notify_task_automation 无 `state` 列**：SELECT/INSERT 不得带 state。
4. **recognize_time 是 DATE 列精确等值**（= 昨日零点），不是范围；造数用 `DATE_SUB(CURDATE(), INTERVAL 1 DAY)`。
5. **批量接口 @Valid List 不校验元素** → /result 改手写校验（8 字段）。
6. **batch/handle 入参嵌套**（`NotifyBatchHandleParam{operator, taskDispatchNodeItems:[...]}`），非扁平。
7. **Date 字段带 @JsonFormat** `yyyy-MM-dd HH:mm:ss` → 传字符串日期，别用时间戳。
8. **query 入参 @JsonProperty snake_case**（`task_type`/`project_order_id`）→ 传驼峰被忽略，过滤失效。
9. **executor_id 必须是登录工长 ucid**（node 维度匹配）：造数 executor = 请求头 X-KE-UCID = Apollo projectManagers。
10. **接口字段名 vs DB 列名**：/result 接口 DTO 用 `receive_time`（= recognize_time 语义）、`key_frame_urls`（= images 语义），落库映射到 `recognize_time`/`images` 列；payload 字段名以实际 DTO 为准。

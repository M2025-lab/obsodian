## 五、背景技术（必填项）

本发明涉及装修履约任务处理与计算机应用技术领域，具体涉及一种基于图像识别结果的工地任务通知方法及系统。

在装修交付流程中，主材（如木门、橱柜、集成吊顶等）的履约由一系列有序任务节点构成，其中存在大量"通知类任务"——例如通知复尺任务：当工地现场的前置工序（如墙面、交界面处理）达到可测量条件时，需要由工地负责人（工长/项目经理）通知供应商或设计师上门服务。

现有技术的工作方式为：**人工到现场检查交界面状态，人工判断是否满足通知条件，再逐条在任务系统中手动填写期望上门时间、上传现场照片并提交通知任务**。其技术现状与不足如下：

1. **判断环节人工化，标准不统一**：是否满足通知条件完全依赖现场人员的个人经验判断，不同人员对同一现场的判定结果可能不同，且无法留证复核；判断依据（交界面照片）由人工随手拍摄，质量与时序无保证。
2. **操作环节逐条化，效率低**：一个工地负责人名下往往有多个工地、每个工地多个品类的通知任务，需逐条进入任务页面分别填写与提交，操作成本随任务数量线性增长，任务堆积时易漏办、迟办。
3. **已有图像识别技术与任务系统割裂**：现有工地摄像头图像识别、照片识别技术通常仅用于施工进度留证或安全巡检，识别结果与任务履约状态机之间没有数据通道；识别结论无法直接驱动任务的状态流转、字段填充或自动执行，两套系统各自独立，无法形成闭环。
4. **缺乏自动化安全机制**：若简单地将识别结果直接触发任务执行，会引入误识别风险、自动化范围失控、人工与自动双通道重复执行等新问题——现有技术中没有针对"识别结论消费侧"的分态处置、灰度控制与幂等防重机制。

因此，需要一种能够将图像识别结果结构化地接入任务履约链路、在保证安全可控的前提下自动完成判断结果消费、内容填充与任务执行的方法。

## 六、设计要点（必填项）

**发明目的 / 解决的技术问题**：针对现有技术中通知类任务人工判断标准不一、逐条操作效率低、图像识别结果与任务系统割裂的问题，提供一种基于图像识别结果的工地任务通知方法，将"人工逐单判断 + 手动提交"升级为"识别预判 + 自动填充 + 批量/自动执行 + 人工兜底"的自动化闭环，并解决自动化过程中的误处置、范围失控与重复执行问题。

**要达到的效果**：通知条件判断标准统一且可留证；任务处理由逐条操作变为按桶批量处理；自动化范围按多级维度灰度可控；人工与自动双通道执行互斥不重复；AI 建议的采纳情况可追溯，形成人机协同反馈数据。

**设计要点及作用**：

1. **四态判定结果模型**：将上游图像识别结论规约为四种互斥状态——可通知、不可通知、无法判断、现场已完成需关闭，并以结构化记录（项目标识 + 品类编码 + 任务类型 + 识别日期 + 判定结果 + 判定备注 + 关键帧图片列表 + 建议上门时间）落库暂存。
   作用：把非结构化的识别输出变成任务系统可消费的确定性输入；"无法判断"态避免误处置（不进入自动执行也不埋没任务）；"现场已完成需关闭"态触发任务关闭提醒，防止已完成工序继续空转考核。

2. **任务节点实例表与自动化记录表的双表联动回填**：任务节点实例表（含期望上门时间、现场照片、AI 采纳情况、通知执行方式字段）为主数据源，自动化记录表兜底；页面填充时优先读节点字段，节点缺失时回溯查询最近一日判定记录。
   作用：人工修改结果（人工锚定优先）不被机器结果覆盖，同时保证无人工痕迹的任务也能获得机器预填内容。

3. **多级灰度开关与失效关闭（fail-closed）策略**：设置功能级开关（按城市、工程部门、作业人员标识三个集合的或命中关系控制功能整体放行）与品类级开关（按品类编码控制自动执行通道），配置缺失视为未命中。
   作用：自动化范围按组织维度与品类维度渐进放量，出错时自动收缩到安全范围，避免全量误执行。

4. **基于状态字段的 CAS 幂等门禁**：为每个任务节点设置通知执行方式字段（未执行/人工批量执行/自动执行），人工批量执行与定时自动执行两个通道在写入时均以"未执行→目标态"的条件更新（CAS）作为唯一放行门禁，更新失败即放弃执行。
   作用：解决人工与自动双通道并发/交叉执行同一任务的重复通知问题，保证同一任务仅被执行一次。

5. **人机协同采纳反馈回写**：在任务节点上记录 AI 建议采纳情况（采纳/未采纳/仅图片采纳/仅时间采纳），由系统对比"机器推荐内容"与"最终提交内容"的差异自动判定，并随任务执行持久化。
   作用：为自动化准确率提供可量化的追溯数据，反哺识别与推荐策略调优；同时作为人工兜底行为的证据链。

6. **分桶查询与批量执行管线**：按判定结果将任务划分为"可通知桶"（判定为可通知且任务激活未完成）、"延期预警桶"（判定为不可通知/无法判断/无记录，且考核时间临近）、"现场已完成桶"（判定为需关闭）三类视图，支持按项目分组聚合、组内按考核紧迫度排序的批量查询；批量执行时逐节点携带明细（图片+时间）并行调用既有单件提交通路，单件失败不阻塞整批，已被其他路径处理的件数单独返回。
   作用：复用既有任务处理链路保证行为一致性，批量并行提升吞吐，结果明细保证可对账。

7. **轮巡暂存与时间窗触达机制**：每日定时轮询最新识别结果写入缓存并预取关键帧图片，页面读取缓存不实时调用上游；摘要计数接口仅在预设时间窗内返回计数，窗口外返回零值。
   作用：削峰上游查询压力，同时避免过期摘要误导现场人员。

## 七、具体实施方式（必填项）

以下结合具体实施例说明本发明的完整技术方案。本领域技术人员根据以下描述能够再现该方案。

### 7.1 系统总体结构

本实施例的系统包括：

- **识别结果接入模块**：接收上游识别服务（对工地摄像头视频与工人上传照片进行分析）批量回调的判定结果，校验后落库暂存；
- **任务节点数据模块**：维护任务调度节点实例表，每个节点对应一道工序的执行状态、期望上门时间、现场照片、执行方式与 AI 采纳情况；
- **自动化记录模块**：维护主材通知任务自动化记录表，存储每次识别的判定明细；
- **查询触达模块**：提供按判定结果分桶的批量查询、摘要计数与页面自动填充能力；
- **执行模块**：提供人工批量一键执行通道与定时自动执行通道，两通道经 CAS 门禁互斥；
- **配置模块**：维护多级灰度开关，采用失效关闭策略。

### 7.2 数据结构

**表 1：主材通知任务自动化记录表**（每维度每日追加一条，只增不改）：

| 字段 | 类型 | 说明 |
|------|------|------|
| project_order_id | BIGINT | 项目订单标识 |
| material_code | VARCHAR | 品类编码 |
| task_type | INT | 任务类型（通知复尺/通知安装/通知送货等） |
| judge_result | TINYINT | 判定结果：0-未判定，1-可通知，2-不可通知，3-无法判断，4-现场已完成需关闭 |
| judge_remark | VARCHAR | 判定备注（含不满足项说明） |
| images | VARCHAR | 关键帧图片地址，逗号分隔 |
| recognize_time | DATE | 识别日期 |
| recommend_visit_time | DATE | 建议上门时间 |
| notify_execute_type | TINYINT | 通知执行方式：0-未执行，1-一键通知（人工批量），2-自动通知 |
| ai_adoption_type | TINYINT | AI 建议采纳情况：0-未处理，1-采纳，2-未采纳，3-图片采纳，4-上门时间采纳 |

索引：(project_order_id, task_type, material_code)。

**表 2：任务节点实例表扩展字段**（在既有任务调度节点表上新增）：

- ai_adoption_type：AI 建议采纳情况（同上枚举）；
- notify_execute_type：通知执行方式（同上枚举）；
- qualified、notice_retain_time、images 等既有字段构成人工锚定数据。

### 7.3 主要流程

**步骤 S1 · 识别结果接入**：上游识别服务按"项目标识+品类编码+任务类型+识别日期+判定结果+备注+图片列表+建议上门时间"八项必填字段批量回调；接入模块逐项校验（含图片列表空元素剔除），校验通过后写入自动化记录表，同维度每日一条追加；执行方式与采纳字段初始化为未处理态。

**步骤 S2 · 分桶查询**：查询模块以作业人员标识为入口，取其名下全部"激活未完成"的任务节点，与自动化记录表按（项目、品类、任务类型、最近识别日期）关联：

- 判定为"可通知"的进入**可通知桶**：页面展示建议上门时间（支持修改）与判定关键帧（默认三张可展开），按项目分组、组内按考核时间升序；
- 判定为"不可通知/无法判断"或无识别记录的，且考核时间与当前时间差值不超过阈值（如 3 天）或已超期的，进入**延期预警桶**，未经系统判定的任务同样露出；
- 判定为"现场已完成需关闭"的进入**现场已完成桶**，触发面向作业人员的关闭提醒推送。

**步骤 S3 · 页面自动填充（双表联动）**：进入通知页面时优先读取任务节点实例表中的期望上门时间与图片（人工锚定优先）；当节点缺失图片或时间时，回溯自动化记录表最近一日判定行兜底填充。灰度开关未命中时填充接口返回空对象（失效关闭）。用户修改后的时间与图片回写暂存，供后续执行使用。

**步骤 S4 · 人工批量一键执行**：用户在可通知桶勾选多个任务后一键提交；执行模块对每个任务节点以"通知执行方式=未执行"为条件执行 CAS 更新（未执行→一键通知），更新成功者携带各自明细（图片+期望上门时间）并行调用既有的单件任务提交通路（复用原有状态流转、下游通知、节点推进逻辑），单件异常不阻塞整批；CAS 失败者（已被其他路径处理）单独计数返回。同时记录本次操作涉及全部任务的操作快照（含被勾选与未勾选项），供事后追溯。

**步骤 S5 · 定时自动执行**：定时任务扫描自动化记录表中"判定=可通知 且 执行方式=未执行 且 识别日期=昨日"的候选；对每个候选先经品类级开关过滤，再按（项目+品类）反查任务节点并去重；以"执行方式=未执行→自动通知"的 CAS 更新作为放行门禁，成功后调用与 S4 相同的单件提交通路完成通知，返回候选数、执行数、跳过数、失败数四项指标。

**步骤 S6 · 采纳反馈回写**：任务执行时对比机器推荐内容（自动化记录表中的建议上门时间与关键帧）与最终提交内容（节点实际提交的时间与图片）的差异，自动判定采纳情况（全部一致-采纳；均不一致-未采纳；仅图片一致-图片采纳；仅时间一致-时间采纳），写入任务节点的 AI 采纳字段，随任务实例持久化。

**步骤 S7 · 轮巡暂存与时间窗触达**：每日固定时刻（如 09:10）轮询全部最新识别结果写入缓存并预取关键帧图片，各页面读缓存；摘要计数接口仅在预设时间窗（如 09:10-10:00、13:00-14:00、19:00-21:00）内返回"可通知 n 个、延期 m 个"计数，窗口外返回零值；每日轮巡发现"现场已完成需关闭"任务时向对应作业人员推送关闭提醒。

### 7.4 实施效果

- 通知条件判断由人工经验判断变为统一的结构化四态判定，判定依据（关键帧）随任务留证可复核；
- 逐条手动提交变为分桶批量一键执行，处理成本随任务数的增长由线性人工操作降为一次批量操作；
- 灰度开关支持按城市/工程部门/作业人员/品类渐进放量，配置缺失自动失效关闭；
- CAS 门禁保证人工与自动双通道对同一任务互斥执行，杜绝重复通知；
- AI 采纳字段沉淀人机协同数据，可统计自动化建议的采纳率并反哺识别策略。

- 父需求：[[00.需求/通知复尺自动化/通知复尺自动化-识别结果应用与驳回记录-技术方案]]（记录侧已实现待上线：`material_notify_execute_record` 表 + handleNode 四挂载点）
- 本期：基于记录表提供**纯拉数查询接口**（运营/数据同学消费，无前端配合），挂既有 BackDoorController（后门拉数惯例：Controller 直连 Dao，无 Service/VO 层）；汇总指标已确认收敛为四个 count：提交总数、提交中经系统识别数、驳回总数、驳回中经系统识别数（识别覆盖观测；应用率/驳回率等 §4.5 指标不进本期接口，需要时另行拉数）

## 2、需求理解[必选]

| # | 需求 | 口径 |
|---|---|---|
| 1 | 汇总接口 | 四个 count：①提交记录总数（record_type=1）②提交中经系统识别数（record_type=1 AND recognized=1）③驳回记录总数（record_type=2）④驳回中经系统识别数（record_type=2 AND recognized=1）。recognized 由写入侧在事件时刻快照（识别表有无记录，doRecord :126），提交/驳回两类记录均带，查询侧零写入改动 |
| 2 | 趋势接口 | 同筛选条件，按天（`DATE_FORMAT(event_time,'%Y-%m-%d')`）返回四个 count 的序列 |
| 3 | 明细分页接口 | 下钻到单条记录（核对识别覆盖 / 排查漏记） |
| 4 | 筛选维度 | 时间范围（必备，`event_time` 口径）+ 品类 + 执行方式 + 识别判定 + 城市 gbCode，均可选；**工程部不支持（已确认不做**：departmentCode 仅能经订单中心 RPC 逐单获取（ProjectOrderManagerImpl:153-158），聚合报表无反查通道） |
| 5 | 形态 | POST + JSON，只出 count 原值不算比率（覆盖率由调用方按需自行相除） |

## 3、详细设计

### 3.1 前置改动：新表增加 gb_code 冗余列（建表前，零迁移成本）

记录方案 §7 的 DDL **尚未交 DBA 执行**，直接在建表语句中加列：`gb_code VARCHAR(32) DEFAULT NULL COMMENT '城市国标编码（冗余自 task_dispatch.gb_code）'`。

写入侧 `NotifyExecuteRecordServiceImpl.doRecord` 回填 `taskNode.getGbCode()`——联表查询 BaseTaskDispatch 已带出 `task.gb_code as gbCode`（TaskDispatchNodeExtMapper.xml:13），**零额外查询、零 RPC**；gb_code 为空的记录该维度筛选不命中，明细可查（`gbCode IS NULL` 属数据质量问题，不在本方案修复）。Model/Example/XML 用既有生成脚本按新列重生成。

不新增索引：报表低频，时间窗经 `idx_record_time(record_type, event_time)` 收敛后按 gb_code 扫行可接受，避免写放大。

### 3.3 汇总/趋势 SQL：条件聚合，单次往返

一条 SQL 单行返回四个 count（趋势同款按 `DATE_FORMAT(event_time,'%Y-%m-%d')` GROUP BY 多行，别名即 DTO 属性名，resultType 直接映射）：

```
submitCount            = IFNULL(SUM(record_type=1), 0)
submitRecognizedCount  = IFNULL(SUM(record_type=1 AND recognized=1), 0)
rejectCount            = IFNULL(SUM(record_type=2), 0)
rejectRecognizedCount  = IFNULL(SUM(record_type=2 AND recognized=1), 0)
```

所有可选筛选条件（materialCode/notifyExecuteType/judgeResult/gbCode）拼入 WHERE（`<if>` 动态段，公共 `Stat_Where_Clause` sql 片段两语句复用），时间条件必备。不算比率，count 原样出。

### 3.4 明细分页：纯 Example，无自定义 SQL

BackDoorController 内拼 Example：时间 Between + 各可选筛选等值条件（含 recordType）+ `orderByClause("event_time desc, id desc")` + `limitStart/limitSize`（pageNum 默认 1、pageSize 默认 20 上限 200），`countByExample` 出 total（total=0 短路不查 rows）。返回 `{total, rows}`，rows 为 Model 全字段（含 gb_code、操作人、事件时间、judge_result、applied、adoption），不另建 VO。

## 4、接口改动

| # | 接口路径 | 接口文档 | 改动点 | 估时 |
|---|---|---|---|---|
| 1 | POST `/backdoor/notifyRecord/statSummary` | 后门拉数：指标汇总。body=StatParam JSON：`startTime/endTime` 必填（`yyyy-MM-dd HH:mm:ss`，缺失返回 fail），`materialCode/notifyExecuteType/judgeResult/gbCode` 可选；出参 `ResultDTO<StatDTO>`：`submitCount / submitRecognizedCount / rejectCount / rejectRecognizedCount` 四个 count | BackDoorController:1027 新增端点 → MaterialNotifyExecuteRecordDao.statSummary → Ext XML `statSummary`（3.3） | |
| 2 | POST `/backdoor/notifyRecord/statTrend` | 后门拉数：指标趋势。body 同 #1；出参 `ResultDTO<List<StatDTO>>`：`[{statDate,submitCount,submitRecognizedCount,rejectCount,rejectRecognizedCount}]` 按天升序 | BackDoorController:1037 → Dao.statTrend → Ext XML `statTrend`（GROUP BY DATE_FORMAT） | |
| 3 | POST `/backdoor/notifyRecord/page` | 后门拉数：明细分页。body=StatParam + `recordType`(可选) + `pageNum/pageSize`（默认 1/20，上限 200）；出参 `ResultDTO<{total, rows}>`，rows 为记录表全字段 | BackDoorController:1047 → 纯 Example（3.4），无新增 SQL | |

## 7、风险评估

- 聚合接口为低频人工拉数：时间范围必填 + `idx_record_time` 收敛扫描区间，单条 SQL 单次往返（3.3，无循环查询）；明细分页强制 limit（pageSize 上限 200）。无性能风险。

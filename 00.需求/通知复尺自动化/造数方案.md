# 复尺通知自动化 · 造数方案（测试库）

> 适用：edar-starlord **local profile** → 测试库 `m10666.mars.test.mysql.ljnode.com:10666`
> 原则：**不新建任何数据表**（含 TEMPORARY TABLE），全部纯 INSERT / 经接口造数，AUTOTEST 前缀便于清理，文件头自带清理段可重跑。
> 源文件：`doc/notify_automation_seed_v2.sql`（造数 SQL）+ `doc/notify_automation_execute_plan.md`（执行方案）；本文件为 wiki 侧落库版。

## 二、三段式造数

### 阶段一：task_dispatch（5 行）
- 唯一键 `(project_order_id, material_code)`；公共列：`task_type=3`、`process_status=2`、`state=1`、`mode=0`、`sale_type=1`、`source_type=0`、`gb_code=110000`、`node_task='20,60'`、`node_path='20000,60000'`。
- `node_task` 必须配 `20,60`：handleNode 完成要靠 `getNextNodeType(node_task,20)` 激活下一节点。

### 阶段二：task_dispatch_node（11 行 = 6 主节点 + 5 次节点）
- **主节点 6 行**（node_type=20、process_status=2、executor_id=88888888）：
  - M01~M04 各 1 行；**M05 同 dispatch 造 restart=0/1 两行** → 验证「同 (task_dispatch_id, node_type) 保留 restart 最大」去重，保留行 restart=1 且带 images/notice_retain_time。
  - M02 / M05(restart=1) 带 images + notice_retain_time（auto-fill node 优先断言用）；M01/M03/M04 不带（走 automation 兜底）。
  - `remarks='AUTOTEST|Jx'` 行标记。
- **次节点 5 行**（node_type=60、process_status=1、`INSERT...SELECT` 从 dispatch 生成，每 dispatch 一行，remarks='AUTOTEST|NEXT'）：handleNode 激活后 process_status 1→2 可观测。

### 阶段三：material_notify_task_automation（5 行）——**必须经 /result 接口造**
- 不能直插 SQL：/result 接口内部做校验 + images 逗号拼接 + `notify_execute_type=0`/`ai_adoption_type=0` 固定落库。
- 造法二选一：
  1. 跑 `doc/test_notify_interfaces.sh` STEP0（日期动态计算）；
  2. 执行 seed SQL 末尾 SELECT 生成 JSON payload → `curl -X POST http://localhost:8080/api/recognize/task/result -H 'X-KE-UCID: 88888888' -d '<payload>'`。
- 关键口径：`recognize_time=昨天`（T+1 语义，服务按 `recognize_time = DATE_SUB(CURDATE(), INTERVAL 1 DAY)` 精确等值查）；`recommend_visit_time=今天+3d`；`judge_result` 按品类（M01=1 M02=2 M03=3 M04=4 M05=1）。

## 三、Apollo 开关（先配开关，再造数）

```json
// 开关A  notification.remeasure.automation.open   —— 功能级，batch/query、summary、auto-fill、save 依赖
{ "cities": [], "projectManagers": ["88888888"], "departments": [] }

// 开关B  notification.remeasure.automation.autoNotify —— 品类级，auto/execute 按 material_code 匹配
{ "AUTOTEST_M05": { "cities": [], "projectManagers": ["88888888"], "departments": [] } }
```

- 语义（代码核实）：**空数组 = 该维度不参与匹配（全放开）；三数组全空/未配置 = 永不命中（fail-closed）**。
- M01 故意不配开关B → auto/execute 计入 skipped（验证跳过不阻断）。
- X-KE-UCID 三处必须一致：`node.executor_id`（造数）= 请求头 `X-KE-UCID`（88888888）= Apollo `projectManagers`。

## 四、执行顺序与断言

| STEP | 内容 | 断言 |
|---|---|---|
| 0 | 配 Apollo 开关A/B | — |
| 1 | 跑 seed_v2.sql 造 task_dispatch(5)+node(11) | 行数 5 / 11 |
| 2 | 经 /result 造 automation(5) + 负例 | code=2000；负例 4004 |
| 3 | batch/query（入参 **snake_case**：`task_type`/`project_order_id`） | notify=2、delay=2；projectOrderId=9100000001 → notify 1 组 + delay 1 组；M04 不出现 |
| 4 | summary | 窗口内 2/2；窗口外 0/0（窗口：09:10-10:00 / 13:00-14:00 / 19:00-21:00） |
| 5 | auto-fill | M01 automation 兜底；M05 node 优先 |
| 6 | save（Date 传**字符串** `yyyy-MM-dd HH:mm:ss`） | M01 node 写入，复查 node 优先 |
| 7 | auto/execute（无 body） | 首次 2/1/1/0；复测 0/0/0/0 |
| 8 | batch/handle（**嵌套** `taskDispatchNodeItems`，nodeId 不得重复） | success=1 + 幂等 already=1 |

## 五、DB 校验与清理

```sql
-- 造数行数
SELECT 'task_dispatch' tbl, COUNT(*) FROM task_dispatch WHERE material_code LIKE 'AUTOTEST%'
UNION ALL SELECT 'task_dispatch_node', COUNT(*) FROM task_dispatch_node WHERE remarks LIKE 'AUTOTEST|%';

-- /result 落库（STEP2 后）：预期 judge 1/2/3/4 各 1 条(judge=1 共 2 条)，notify_execute_type=0
SELECT judge_result, notify_execute_type, COUNT(*) FROM material_notify_task_automation
WHERE judge_remark LIKE 'AUTOTEST%' AND recognize_time = DATE_SUB(CURDATE(), INTERVAL 1 DAY)
GROUP BY judge_result, notify_execute_type ORDER BY judge_result;

-- handle/auto 后状态：M01 → notify_execute_type=1；M05 → =2
SELECT material_code, notify_execute_type FROM material_notify_task_automation
WHERE judge_remark LIKE 'AUTOTEST%' AND recognize_time = DATE_SUB(CURDATE(), INTERVAL 1 DAY) AND judge_result = 1;

-- 清理（测试结束必做）
DELETE FROM material_notify_task_automation WHERE judge_remark LIKE 'AUTOTEST%';
DELETE FROM task_dispatch_node WHERE remarks LIKE 'AUTOTEST|%';
DELETE FROM task_dispatch WHERE material_code LIKE 'AUTOTEST%';
```

## 六、造数踩坑速记（详细见「开发总结.md」第 5、6 节）

1. **不建临时表**：autotest TEMPORARY TABLE 跨 session 失效（v1 废弃根因）→ v2 纯 INSERT。
2. **task_dispatch_node 无 `source` 列**（model 有、DB 无）：INSERT 列清单必须去掉。
3. **recognize_time 是 DATE 列精确等值**（= 昨日零点），不是范围；造数用 `DATE_SUB(CURDATE(), INTERVAL 1 DAY)`。
4. **批量接口 @Valid List 不校验元素** → /result 改手写校验（详见知识沉淀）。
5. **batch/handle 入参是嵌套结构**（`NotifyBatchHandleParam{operator, taskDispatchNodeItems:[{taskDispatchNodeId, noticeRetainTime, images, ...}]}`），非扁平；返回仅 `{successCount, alreadyHandledCount}`。
6. **Date 字段带 @JsonFormat `yyyy-MM-dd HH:mm:ss`** → 传字符串日期，别用时间戳。
7. **query 入参 @JsonProperty snake_case**（`task_type`/`project_order_id`）→ 传驼峰被忽略，过滤失效。

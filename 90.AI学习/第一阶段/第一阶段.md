## Day1：Python 基础语法

> 目标：掌握 Agent 开发中最常用的 Python 语法，不钻冷门特性。
>
> 📄 详细学习计划见 [[day1]]。

### ① 理论（What）

必须掌握的数据结构与语法：

```text
变量 / int / float / str / bool
List  （对应 Java ArrayList）
Dict  （对应 Java HashMap）
Set
tuple / unpacking
字符串 f-string
条件 / 循环
函数 def
class / __init__ / self
继承
异常 try/except/finally
模块 import
包 __init__.py
```

### ② 原理（Why）

对比 Java 理解 Python 的设计：

| 特性       | Java              | Python                    |
| -------- | ----------------- | ------------------------- |
| 类型        | 静态强类型             | 动态类型，运行时推断                 |
| 方法第一个参数   | 无 self            | 必须显式 `self`                |
| 接口/继承     | `interface`/`extends` | 鸭子类型，继承语法更轻                |
| 属性        | 必须先声明字段            | 可动态添加                     |
| 入口        | `public static void main` | `if __name__ == "__main__":` |

**为什么 Agent 用 Python**：

- 动态类型 → 快速拼接 LLM 返回的 JSON 成对象
- 鸭子类型 → Tool 实现不需要统一接口，有 `__call__` 就能跑
- 生态 → LLM / RAG / Agent 的官方 SDK 都先发 Python

### ③ 企业实践（How）

```python
class Tool:
    def __init__(self, name: str):
        self.name = name

    def run(self, input: dict) -> str:
        raise NotImplementedError

class QueryProjectTool(Tool):
    def run(self, input: dict) -> str:
        project_id = input.get("projectId")
        if not project_id:
            raise ValueError("projectId 不能为空")
        return f"项目 {project_id} 的数据"

if __name__ == "__main__":
    tool = QueryProjectTool("query_project")
    print(tool.run({"projectId": "826051217000001469"}))
```

### ④ 编码（Code）

写一个 `Tool` 基类 + 两个具体 Tool（`query_project`、`query_task`），用 try/except 捕获参数错误并打印友好错误信息。

### 今天必须达到

- 能不查文档写出一个带继承和异常处理的 class
- 能解释 `self` 为什么必须显式写
- 能解释 `if __name__ == "__main__"` 的作用

## Day2：venv + pip + 模块

> 目标：能管理项目依赖，理解 Python 的虚拟环境与包管理。
>
> 📄 详细学习计划见 [[day2]]。

### ① 理论（What）

```text
venv          — 虚拟环境（隔离依赖，类似 Java 的多项目 jar 隔离）
pip           — 包管理（类似 Maven）
requirements.txt / pyproject.toml — 依赖声明（类似 pom.xml）
import        — 模块导入
__init__.py   — 包标记 + 暴露 API
```

### ② 原理（Why）

**为什么需要 venv**：

```text
项目 A 依赖 httpx 0.27
项目 B 依赖 httpx 0.24
→ 全局装一个版本会冲突
→ venv 给每个项目独立一套依赖
```

对比 Java：Java 靠 Maven/Gradle 把依赖装进各自 `~/.m2`，编译时打包；Python 靠 venv 在**运行环境**层面隔离。

### ③ 企业实践（How）

```bash
python -m venv .venv
source .venv/bin/activate        # 激活（Windows: .venv\Scripts\activate）
pip install httpx pydantic fastapi
pip freeze > requirements.txt     # 锁定版本
pip install -r requirements.txt   # 还原依赖
deactivate
```

目录组织：

```text
agent/
├── __init__.py
├── tools/
│   ├── __init__.py
│   ├── query_project.py
│   └── query_task.py
└── main.py
```

### ④ 编码（Code）

1. 新建 venv，安装 `httpx`、`pydantic`、`fastapi`
2. 把 Day1 的 Tool 拆成 `tools/` 包
3. `main.py` 用 `from tools.query_project import QueryProjectTool` 导入并运行
4. `pip freeze > requirements.txt`

### 今天必须达到

- 能解释 venv 解决什么问题
- 能用 `requirements.txt` 还原一个全新环境的依赖
- 能解释 `__init__.py` 的作用

## Day3：类型注解 + Pydantic

> 目标：会用类型注解 + Pydantic 定义数据模型并自动校验。这是后面 Structured Output 和 Tool Schema 的基础。
>
> 📄 详细学习计划见 [[day3]]。

### ① 理论（What）

```text
类型注解         — str / int / list[str] / dict[str, int] / Optional / Union
Pydantic        — BaseModel，运行时校验 + 自动转 JSON
Field           — 字段描述、默认值、约束
model_dump()    — 转回 dict
model_validate()— 从 dict 构造并校验
```

### ② 原理（Why）

**为什么 Agent 必须用 Pydantic**：

```text
LLM 输出 JSON
   ↓
Pydantic 校验
   ↓
变成强类型对象
   ↓
业务代码安全使用
```

对比 Java：

| 场景          | Java             | Python + Pydantic    |
| ----------- | ---------------- | -------------------- |
| 数据模型        | POJO / Record    | BaseModel            |
| JSON ↔ 对象  | FastJSON @JSONField | `model_validate` / `model_dump_json` |
| 字段校验        | `@Valid` + 注解      | `Field(..., constraints)` 内置         |

**为什么类型注解不影响运行但有价值**：

```python
def query(project_id: str) -> dict:   # 注解不强制，但 IDE/mypy 能检查
    ...
```

类型注解是「给人和工具看的」，运行时不报错，但 Agent 框架（LangChain / LangGraph）会**读取注解**来自动生成 Tool Schema。

### ③ 企业实践（How）

```python
from pydantic import BaseModel, Field
from typing import Optional

class ProjectQuery(BaseModel):
    projectId: str = Field(..., description="项目订单ID，如 826051217000001469")
    recheckOnly: bool = Field(default=False, description="是否只查复尺任务")

class Project(BaseModel):
    projectId: str
    name: str
    notifiable: bool
    reason: Optional[str] = None

# 从 LLM 返回的 JSON 构造
raw = '{"projectId":"826051217000001469","name":"XX项目","notifiable":true}'
p = Project.model_validate_json(raw)
print(p.model_dump())           # → dict
print(p.model_dump_json())      # → JSON 字符串
```

### ④ 编码（Code）

1. 定义 `ProjectQuery` / `Project` / `NotifyTask` 三个模型
2. 故意传一个缺字段的 JSON，观察 Pydantic 抛出的 `ValidationError`
3. 写一个 `parse_llm_output(raw_json: str) -> Project`，把 LLM 输出转成对象

### 今天必须达到

- 能解释「LLM 输出 JSON → Pydantic → 强类型对象」这条链路
- 能解释为什么 Tool 的参数模型要写 `Field(description=...)`
- 能捕获 `ValidationError` 并提取缺哪个字段

## Day4：async / await

> 目标：理解 Python 异步并发。后面 Agent 大量涉及 LLM 请求、Tool 调用、Streaming、并发，async 是核心。
>
> 📄 详细学习计划见 [[day4]]。

### ① 理论（What）

```text
async def        — 定义协程
await            — 等待一个 awaitable（协程 / Task / Future）
asyncio          — 事件循环库
asyncio.gather() — 并发执行多个协程
asyncio.create_task() — 包成 Task 并发跑
```

### ② 原理（Why）

**为什么 Agent 需要 async**：

```text
场景：用户问「查项目 123 的通知任务 + 复尺结果 + 业务规则」

同步写法：
query_project()  ──200ms──►
query_task()      ──200ms──►   总 600ms

异步写法：
await gather(query_project(), query_task(), query_rule())
   └ 三个并行，总 200ms
```

对比 Java：

| 概念          | Java                        | Python            |
| ----------- | --------------------------- | ----------------- |
| 异步单元        | `CompletableFuture` / 虚拟线程    | 协程 `async def`    |
| 等待          | `.join()` / `.get()`         | `await`           |
| 并发汇总        | `allOf(...)`                 | `asyncio.gather`  |
| 线程模型        | 线程池 / 虚拟线程                   | 单线程事件循环 + 协程      |

**关键理解**：async 不是多线程，是**单线程内切换任务**。遇到 IO（网络请求）就让出事件循环给别人跑，IO 完了再回来。所以 async 只对 IO 密集有用，CPU 密集该用多进程。

**陷阱**：在 async 函数里调同步阻塞代码（如 `time.sleep` / `requests.get`）会**卡死整个事件循环**。必须用异步版本（`asyncio.sleep` / `httpx.AsyncClient`）。

### ③ 企业实践（How）

```python
import asyncio
import httpx

async def query_project(project_id: str) -> dict:
    async with httpx.AsyncClient() as client:
        resp = await client.get(f"http://java-service/project/{project_id}")
        return resp.json()

async def query_task(project_id: str) -> dict:
    async with httpx.AsyncClient() as client:
        resp = await client.get(f"http://java-service/task?projectId={project_id}")
        return resp.json()

async def main():
    # 并发查两个接口
    project, task = await asyncio.gather(
        query_project("826051217000001469"),
        query_task("826051217000001469"),
    )
    print(project, task)

asyncio.run(main())
```

### ④ 编码（Code）

1. 写 `async def query_project` / `query_task`，内部 `await asyncio.sleep(0.2)` 模拟网络
2. 用 `asyncio.gather` 并发跑，打印总耗时（应≈200ms 不是 400ms）
3. 故意在 async 里写 `time.sleep(1)`，观察并发变成串行

### 今天必须达到

- 能解释「async 不是多线程」
- 能解释为什么 async 函数里不能用 `requests`（阻塞事件循环）
- 能用 `asyncio.gather` 把多个 Tool 调用并发起来

## Day5：HTTP（httpx async）

> 目标：用 httpx 异步调用 Java Spring Boot 接口，封装成可复用 Client。这是 Tool 调用 Java 服务的底层通道。
>
> 📄 详细学习计划见 [[day5]]。

### ① 理论（What）

```text
httpx.AsyncClient    — 异步 HTTP 客户端
GET / POST / PUT      — 常用方法
params               — query 参数
json                 — 请求体（自动序列化）
headers              — 鉴权 / Content-Type
timeout              — 超时
raise_for_status()   — 状态码非 2xx 抛异常
```

### ② 原理（Why）

**为什么选 httpx 不选 requests**：

| 特性      | requests     | httpx                |
| ------- | ------------ | -------------------- |
| 异步      | 不支持（阻塞事件循环）  | 原生 `AsyncClient`     |
| HTTP/2  | 不支持          | 支持                   |
| API 兼容  | —            | 几乎同 requests，迁移成本极低   |
| 连接复用    | Session      | AsyncClient 长连接      |

**为什么用 `async with`**：

```text
AsyncClient 内部维护连接池
async with 确保用完释放连接
不释放 → 连接泄漏 → Java 端连接池打满
```

### ③ 企业实践（How）

```python
import httpx
from typing import Optional

class JavaServiceClient:
    def __init__(self, base_url: str, token: Optional[str] = None):
        self._base_url = base_url.rstrip("/")
        self._headers = {"Authorization": f"Bearer {token}"} if token else {}

    async def query_project(self, project_id: str) -> dict:
        async with httpx.AsyncClient(base_url=self._base_url, timeout=5.0) as client:
            resp = await client.get(
                f"/project/{project_id}", headers=self._headers
            )
            resp.raise_for_status()
            return resp.json()

    async def submit_notify(self, project_id: str, task_ids: list[str]) -> dict:
        async with httpx.AsyncClient(base_url=self._base_url, timeout=10.0) as client:
            resp = await client.post(
                "/notify/submit",
                json={"projectId": project_id, "taskIds": task_ids},
                headers=self._headers,
            )
            resp.raise_for_status()
            return resp.json()
```

### ④ 编码（Code）

1. 封装 `JavaServiceClient`，含 `query_project` / `query_task` / `submit_notify` 三个方法
2. 统一异常处理：把 `httpx.HTTPStatusError` 转成业务可读的错误信息
3. 配置 `timeout` 和重试（`httpx` 不自带重试，可装 `tenacity` 或手动重试一次）
4. 在本地起一个 mock Java 接口（FastAPI 也行）测试通

### 今天必须达到

- 能解释为什么不用 `requests` 而用 `httpx.AsyncClient`
- 能写出带超时、鉴权头、异常处理的 Client
- 能解释 `raise_for_status()` 不调会怎样（4xx/5xx 被当成功返回）

## Day6：FastAPI

> 目标：用 FastAPI 把 Python 能力暴露成 HTTP API，作为 Java / 前端调 Agent 的入口。
>
> 📄 详细学习计划见 [[day6]]。

### ① 理论（What）

```text
FastAPI()                 — 应用实例
@app.get / @app.post      — 路由
Pydantic BaseModel        — 请求体自动校验（同 Day3）
response_model             — 响应体自动序列化
Depends()                 — 依赖注入（类似 Spring @Autowired）
BackgroundTasks            — 后台异步任务
uvicorn                    — ASGI 服务器，跑 FastAPI
```

### ② 原理（Why）

对比 Java Spring Boot：

| 概念          | Spring Boot              | FastAPI                |
| ----------- | ----------------------- | ---------------------- |
| 路由          | `@GetMapping`            | `@app.get`             |
| 请求体校验       | `@Valid` + DTO           | Pydantic BaseModel 自动 |
| 依赖注入        | `@Autowired`            | `Depends()`            |
| 异步          | WebFlux / 虚拟线程           | 原生 async def          |
| 启动          | Tomcat 内嵌               | uvicorn (ASGI)         |
| API 文档      | Swagger（需引入）             | 内置 `/docs`             |

**为什么 Agent 用 FastAPI**：

- 原生 async → 能直接 `await` LLM 调用，不阻塞
- Pydantic 集成 → 请求/响应自动校验
- 内置 Swagger → Java 端看 `/docs` 就能对接

### ③ 企业实践（How）

```python
from fastapi import FastAPI, Depends, HTTPException
from pydantic import BaseModel
from .java_client import JavaServiceClient

app = FastAPI(title="Construction Agent API")

class QueryRequest(BaseModel):
    question: str
    projectId: str

class QueryResponse(BaseModel):
    answer: str
    data: dict

def get_java_client() -> JavaServiceClient:
    return JavaServiceClient(base_url="http://localhost:8080")

@app.post("/agent/query", response_model=QueryResponse)
async def query(req: QueryRequest, java: JavaServiceClient = Depends(get_java_client)):
    try:
        project = await java.query_project(req.projectId)
        # 这里后面接 LLM，今天先直接返回
        return QueryResponse(answer=f"项目 {req.projectId}", data=project)
    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))
```

启动：

```bash
uvicorn main:app --reload --port 8000
# 打开 http://localhost:8000/docs 看 Swagger
```

### ④ 编码（Code）

1. 起 FastAPI，写 `/agent/query` 接口
2. 用 `Depends` 注入 Day5 的 `JavaServiceClient`
3. `response_model` 用 Pydantic，返回自动序列化
4. 起 uvicorn，在 `/docs` 测试通过

### 今天必须达到

- 能解释 FastAPI 为什么天然 async
- 能用 `Depends` 做依赖注入
- 能在 `/docs` 调通一个带 Pydantic 校验的接口

## Day7：整合 —— FastAPI 调用 Java 服务

> 目标：把前 6 天的成果串起来，完成本阶段输出项目 —— Python API 调用 Java Spring Boot。
>
> 📄 详细学习计划见 [[day7]]。

### ① 理论（What）

本阶段的最终形态：

```text
用户/前端
   ↓ HTTP
Python FastAPI（async + Pydantic）
   ↓ httpx async
Java Spring Boot（业务逻辑 / 权限 / 事务）
   ↓
MySQL / Redis / Kafka / ES
```

整合涉及的全部知识：

```text
Day1 class + 异常      → Tool 基类
Day2 venv + 模块        → 项目结构
Day3 Pydantic          → 请求/响应模型
Day4 async/await       → 并发调 Java
Day5 httpx             → JavaServiceClient
Day6 FastAPI           → 对外 API
```

### ② 原理（Why）

**为什么先打通这条链路再学 LLM**：

```text
后面 Tool Calling 的本质，就是：
   LLM 决定调哪个 Tool
       ↓
   Tool 内部 = httpx 调 Java API（今天做的）
       ↓
   结果回给 LLM

如果今天没打通 Python→Java，
后面 Tool Calling 会卡在「Tool 怎么调业务」上。
```

**职责划分**（对应主计划第 9 章）：

```text
Python 负责：AI 能力、Agent、Tool 调用入口
Java  负责：业务逻辑、权限、事务、数据库
```

### ③ 企业实践（How）

项目结构：

```text
construction-agent/
├── .venv/
├── requirements.txt
├── main.py                    # FastAPI 入口
├── models.py                  # Pydantic 模型
├── java_client.py             # httpx 调 Java
├── tools/
│   ├── __init__.py
│   ├── base.py                # Tool 基类
│   ├── query_project.py
│   └── query_task.py
└── config.py                  # base_url / token
```

`tools/query_project.py`：

```python
from .base import Tool
from ..java_client import JavaServiceClient

class QueryProjectTool(Tool):
    name = "query_project"
    description = "根据 projectOrderId 查询项目信息"

    def __init__(self, java: JavaServiceClient):
        self._java = java

    async def run(self, project_id: str) -> dict:
        return await self._java.query_project(project_id)
```

`main.py`：

```python
from fastapi import FastAPI, Depends
from models import QueryRequest, QueryResponse
from java_client import JavaServiceClient
from tools.query_project import QueryProjectTool

app = FastAPI()

def get_java() -> JavaServiceClient:
    return JavaServiceClient(base_url="http://localhost:8080")

@app.post("/agent/query", response_model=QueryResponse)
async def query(req: QueryRequest, java: JavaServiceClient = Depends(get_java)):
    tool = QueryProjectTool(java)
    project = await tool.run(req.projectId)
    return QueryResponse(answer="ok", data=project)
```

### ④ 编码（Code）

1. 起一个 Java Spring Boot mock 服务（或直接用 FastAPI 假装 Java 端），提供 `/project/{id}`、`/task?projectId=`、`/notify/submit`
2. Python 端按上面结构搭好
3. 并发调两个 Java 接口（`asyncio.gather`）
4. FastAPI `/docs` 调通，打印请求耗时和返回

### 今天必须达到

- 能画出「前端 → Python FastAPI → Java Spring Boot → 中间件」完整链路
- 能解释 Tool 内部为什么就是「httpx 调 Java」
- 能用 `asyncio.gather` 并发调多个 Java 接口
- **本阶段输出项目达成**：Python API 能调用 Java 服务

## 源码阅读计划（每天 30 分钟）

你未来想做的是 **AI Agent 工程师**，不是 AI 使用者。因此每天除了学一个知识点，还要**读源码**。

本阶段读 Python 生态源码（不是 Java Spring AI）：

| 天        | 阅读源码                  | 重点关注什么                          |
| -------- | --------------------- | ------------------------------- |
| Day1-2   | FastAPI `app.py`      | 路由怎么注册、`Depends` 如何解析依赖         |
| Day3     | Pydantic `BaseModel`  | `model_validate` 如何校验、字段如何收集    |
| Day4     | `asyncio` `tasks.py`  | `gather` 如何调度协程、事件循环如何切换        |
| Day5     | `httpx` `_client.py`  | AsyncClient 连接池如何复用、`raise_for_status` 实现 |
| Day6     | FastAPI `routing`     | 请求进来如何匹配路由、调用依赖、序列化响应          |
| Day7     | 一个 Pydantic AI 示例     | 整体如何把 LLM + Tool + Pydantic 串起来 |

每个类/函数，固定回答四个问题：

1. **它解决什么问题？**
2. **它的输入和输出是什么？**
3. **为什么这样设计，而不是另一种方式？**
4. **如果让我自己写，我会怎么实现？**

这会让你不仅会调库，还理解设计思路，为后面学 LangGraph、MCP、RAG 打下基础。

## 阶段验收

### 输出项目

**Construction-Agent V0（Python 底座）**：

```text
Python FastAPI
   ↓ httpx async
Java Spring Boot（或 mock）
```

能跑通：前端发请求 → Python API → 并发调 Java 两个接口 → 返回结果。

### 验收标准

⭐⭐⭐⭐⭐ 能独立完成：

- [ ] 用 venv 管理依赖，`requirements.txt` 可还原
- [ ] 用 Pydantic 定义请求/响应模型并校验
- [ ] 写出 async Tool 基类，内部 httpx 调 Java
- [ ] 用 `asyncio.gather` 并发调多个 Java 接口
- [ ] 用 FastAPI 暴露 `/agent/query`，`/docs` 可调通
- [ ] 能解释 Python→Java 这条链路每一层在干什么

### 自测题

> 为什么 Agent 开发用 Python 而不是纯 Java？
>
> `async` 不是多线程，那它靠什么实现并发？
>
> 为什么 async 函数里不能用 `requests`？
>
> Pydantic 在「LLM 输出 → 业务对象」这条链路里解决什么问题？
>
> Tool 内部调用 Java 服务，本质是在做什么？
>
> FastAPI 的 `Depends` 和 Spring 的 `@Autowired` 有什么异同？

全部能答上来，再进入第二阶段 [[90.AI学习/Agent学习计划|Agent学习计划]] 第 3 章「LLM API」。

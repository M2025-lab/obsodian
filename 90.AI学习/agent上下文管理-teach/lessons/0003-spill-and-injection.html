1. 回顾：三类操作还差两块

Lesson 0001 把手段分成三类，0002 只展开了 ① 压缩。本节补齐 ②③：

2. ② 外置(spill)：桶装不下就存盘，留指针

触发：某个工具结果超过 maxInlineBytes（比如读了 8000 行文件）。

做法：全文存到 spill 文件，上下文里只留预览 + 定位符（locator）。模型需要细节时，按 retrievalHint 去 read/grep。

为什么只留 head/tail？ 模型通常只需要头（文件签名/结构）和尾（报错往往在最后一行），中间细节按需再读。这就是 Claude Code "预算削减" 与 DeepHarness "spill" 殊途同归的地方。

function spillReplacement(result, cap):
  if len(result) <= maxInlineBytes: return result          // 不大 → 内联
  path = spillStore.saveText(result)                        // 全文落盘
  if path == null: return result                            // 落盘失败 → 降级保留内联（绝不丢）
  head = result.head(PREVIEW)
  tail = result.tail(PREVIEW)
  return { preview: head + '…(已外置 ' + len + ' 字符)…' + tail,
           locator: path,
           retrievalHint: 'read/grep 此路径' }              // 替换后绝不超 cap

3. ③ 注入时裁剪(agent-instructions)：往桶里放什么，且别塞爆

这一步决定初始往 Surface 放什么。它管三样：工作区指令（AGENTS.md）、跨会话引用、时间上下文。

关注点做法为什么
字节预算截断AGENTS.md 超预算就截断不能把指令全文无脑塞爆桶
增量刷新文件被 read/write/edit 触碰 → 对应 projection 标脏，下次 compose 重算不必每轮全量重渲染，省成本
按需投射只把"当前 step 打开的"相关投影放进去模型只看当下该看的
 
compose():
  text = render(AGENTS.md)
  if bytes(text) > budget: text = truncate(text, budget)   // 字节预算截断
  return text
on touch(file): dirtyProjections.add(file)                 // 文件被读/写/改 → 标脏
syncInbox(): for p in dirtyProjections: reproject(p)        // 增量重算，不全量

4. 横切：token-meter 是决策的尺子

0001/0002 反复说"读 tokenMeter"。它到底是什么？——所有压缩/外置触发判断的唯一压力来源。

  • 按 Surface 位置计价：回放快照，给每个 surface 节点算 token 数（surface 顺序权威）。
  • 两层计价：固定估计（约 4 字符/token）+ 路由计价（用真实图片/文件单价替换固定启发式）。
  • 单例：压缩决策基于真实 token 压力，不是拍脑袋。

5. 全景地图：把三块拼成闭环

闭环逻辑：③注入时裁剪决定初始放什么 → 进 Surface（桶） → 运行中 token-meter 持续计量，超阈值就触发 ①压缩 或 ②外置 维持水位。这就是"上下文管理"的全貌。

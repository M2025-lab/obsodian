🧠 上下文管理：为什么、是什么、两大做法

学完本节你能：① 用一句话说清"上下文管理解决什么问题"；② 画出 Raw Log ≠ Surface 的关系； ③ 说出 Claude Code 与 DeepHarness 两家思路的相同与不同。 这是理解后面所有机制的总开关。

1. 先从一个真实场景说起

你让一个 coding agent 干活：

  • 读了一个 8000 行的配置文件；
  • 跑了一遍构建，日志 5000 行；
  • 连续改了 20 个文件，每步都有工具调用和结果。

模型每次推理，只能看到"当前上下文窗口"里的东西。窗口是有限的、且按 token 计费。于是问题来了：

一句话定义上下文管理：在有限的、昂贵的窗口里，始终让模型看到"够它做下一个决策的最小信息集"。 不是"塞得越多越好"，而是"留得准"。

2. 心智模型：上下文窗口 = 一个"展示桶"

把上下文窗口想成一个固定容量、按 token 计费的透明桶：

桶的属性对系统的含义
容量固定满了就必须有人决定：哪些拿走、哪些留下、哪些不进桶
整体发送每轮推理，桶被整体发给模型，模型只看桶内
按量计费越满越贵，所以"压缩"本身也要算成本（不能乱调 LLM）

3. 整件事的基石：Raw Log ≠ Surface

这是 DeepHarness 最关键的一句，也是读懂全部机制的开关。记牢：

Raw Log（原始日志） = 完整记录"发生过什么"的 append-only 事件流。可回放、可审计。
Surface（表面投影） = 模型"现在应该看到"的那一份，是 Raw Log 的一个投影（视图）。

关键推论（务必记住）：压缩 ≠ 删除历史。压缩只是"改 Surface 投影"——把原始对话从 Surface 抹掉、换成一条摘要；Raw Log 一行不少。 这带来三大好处：可逆（想恢复就改回投影）、可审计（日志完整）、可调试（能回放）。

4. 两大设计哲学

哲学 A — Claude Code：单一循环 + 5 层懒惰降级阶梯

永远先试最便宜的操作，逐级升级，目标是在"最大化工作记忆"和"最小化缓存失效"间取平衡：

层级手段成本
⑤预算削减：超大工具输出 → 换成"结果已存 X 路径"的指针最便宜
④裁剪：删掉历史里特定大块文本（如巨型 build 日志）低
③微压缩：细粒度、缓存感知的压缩中
②上下文坍缩：读取时合并多条消息（视觉合并不删）中
①自动压缩：调 LLM 把最早对话摘要成一条 system 消息最贵·有损
经济学洞察：CLAUDE.md 不进 system prompt。它被包在标签里当 message 注入，并附"这段可能相关也可能不相关"。 原因纯经济——system prompt 对所有用户完全相同才能共享 90% 折扣的 prompt cache；若 CLAUDE.md 进 system prompt，每个用户单独缓存，产品经济学崩塌。

哲学 B — DeepHarness：事件溯源 + 可插拔 seam

把"发生过什么"和"现在看什么"彻底分开（即第 3 节的 Raw Log/Surface）。压缩、裁剪都是往 Raw Log 追加几条事件 + 改 Surface，日志只增不减，因此干净、可逆、可审计。

维度Claude Code（逆向）DeepHarness（开源）
架构哲学单一循环 + 5 层降级阶梯事件溯源 + 可插拔能力 seam
压缩触发阈值监控，循环内暂停pressure / context-overflow 事件
压缩策略5 层逐级升级，先便宜先确定性剪枝，不够才 LLM 摘要
超大输出预算削减（指针替换）spill（存全文 + locator 预览）
可审计性较隐式极强：Raw Log 完整，Surface 是投影
缓存经济CLAUDE.md 踢出 system promptrequest/header 单独记录

5. 两家的共识（你真正该记住的）

共识 1 · 懒惰降级：先试最便宜的压缩手段，LLM 摘要是最后手段（贵 + 有损）。

共识 2 · 超大输出外置：别把 8000 行塞进桶，存盘 + 预览 + 定位符。名不同（budget reduction / spill），理一样。

共识 3 · 缓存经济优先于便利：共享 prompt cache 比"什么都塞进 system prompt"重要得多。

# 派单二级确认状态 — 影响范围报告  
  
## 变更概述  
  
安装/拆除工从整装组织体系独立后，派单流程新增二级确认环节：`待派单 → 待上级确认 → 待工人确认 → 已接单`。派单状态由 minerva 维护，Cube 仅负责同步到 ES 供前端展示和筛选，**数据不落 Cube 本地 DB**。  
  
---  
  
## 编码体系  
  
| 语义 | ES `dispatchConfirmStatus` | VO `packageDispatchConfirm` | 前端 type=5 |  
|------|---------------------------|-----------------------------|-------------|  
| 无 | 0 | — | — |  
| 待上级确认 | 1 | 2001 | "2001" |  
| 待工人确认 | 2 | 2002 | "2002" |  
  
**收口枚举**：`DispatchConfirmStatusEnum`（es↔vo 转换：1↔2001, 2↔2002）  
  
---  
  
## 跨系统接口  
  
| 方向 | 定义位置 | 实现位置 | 路径 |  
|------|---------|---------|------|  
| minerva → Cube（通知） | `PackageConstructionFeign` | `PackageConstructionController` | `POST /package/dispatch/changeNotice` |  
| Cube → minerva（反查单条） | `MinervaManager.DispatchStatusFeign`（内嵌） | minerva 侧实现 | `POST /dispatch/dispatchConfirmStatus/query` |  
| Cube → minerva（反查批量） | 同上 | minerva 侧实现 | `POST /dispatch/dispatchConfirmStatus/batchQuery` |  
  
---  
  
## 影响的功能  
  
### 需修改  
  
| 功能 | 改动要点 | 涉及代码 |  
|------|---------|---------|  
| **派单状态通知** | 接收 minerva 通知 → 触发 store() 推 ES | `PackageConstructionController.dispatchChangeNotice()` |  
| **施工包列表（经理视角）** | 新增 type=5 筛选 + `packageDispatchConfirm`(2001/2002) 返回 + 排序 | `WorkerServiceImpl`、`EsSearchServiceImpl`、`PackageListParam` |  
| **ES 数据同步（store）** | 推 ES 前反查 minerva 获取 dispatchConfirmStatus，合并后推送 | `PackageStorageServiceImpl.store()`、`MinervaManager` |  
| **ES DTO** | 新增 `dispatchConfirmStatus` 字段（读写双端） | `EsPackageConstruction`、`EsPackageConstructionMessageDTO` |  
  
### 间接影响（逻辑不变，执行路径变化）  
  
| 功能 | 原因 | 风险 |  
|------|------|------|  
| EPX binlog 实时同步 | `store()` 内部新增反查 | 反查失败 catch 不抛异常，ES 缺字段靠 `missing=_last` 防御 |  
| MutationController 手动触发 | 走同一 `store()` 路径 | 同上 |  
  
### 不受影响  
  
| 功能 | 原因 |  
|------|------|  
| 工人端接单/拒单 | minerva 处理，Cube 不干预 |  
| 约工驳回查上级 | 服务者中心内部改造，Cube 无代码改动 |  
| 费用单会签审批 | 独立改造，无耦合 |  
| `package_construction` 表 | 无 DDL |  
| `package_loan_task` 表 | `dispatchStatus` 保持 0/2/3/4 |  
| `DispatchStatusEnum` | 本期不新增值 |  
  
---  
  
## 跨团队依赖（minerva 侧）  
  
1. 实现通知接口调用：二级状态流转时调 Cube `POST /package/dispatch/changeNotice`  
2. 提供反查接口：`POST /dispatch/dispatchConfirmStatus/query` + `batchQuery`  
3. ES mapping：索引 1047900333 新增 `dispatch_confirm_status`（integer）  
4. 存量刷数：补写 ES 存量文档的 `dispatch_confirm_status`

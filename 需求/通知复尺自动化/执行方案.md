# 识别结果接收接口与落库方案（一期）

> 本部分为「接收上游判断结果 → 落库」的落地设计。落点工程：**edar-starlord（主材任务系统）**。
> 数据表：`material_notify_task_automation`（主材通知任务自动化记录表）。
> 原则：**只新增、不更新**；一期仅暂存，不触发通知/任务业务逻辑。

## 1. 接口定义

| 项 | 值 |
| --- | --- |
| 路径 | `POST /api/deduct/task/result` |
| 调用方 | 调度层 → 主材（edar-starlord） |
| 用途 | 接收上游识别结果并暂存 |
| 请求体 | 见下方 `NotifyTaskResultParam` |
| 响应 | `ResultDTO<Void>`，成功返回 `success()` |
| 暴露形式 | **Controller + Feign**（参照 `SupplierMessageSyncFeign` / `SupplierMessageSyncController`） |

接口形式选型：api 模块定义 `@FeignClient("edar-starlord")` 接口，web 模块 Controller 实现之，供调度层 Feign 调用。

## 2. 数据表 DDL（最终版）

```sql
CREATE TABLE `material_notify_task_automation` (
    `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键',
    `receive_time` DATE DEFAULT NULL COMMENT '主材接收上游识别结果日期，T的时间基准',
    `project_order_id` BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '项目订单id',
    `material_code` VARCHAR(50) NOT NULL DEFAULT '' COMMENT '品类编码',
    `material_name` VARCHAR(100) NOT NULL DEFAULT '' COMMENT '品类名字',
    `task_type` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '任务类型',
    `task_name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '任务类型名称',

    `notify_status` TINYINT NOT NULL DEFAULT 1 COMMENT '通知任务状态：1-未完成通知任务，2-已完成通知任务',

    `judge_result` TINYINT DEFAULT NULL COMMENT '最新系统判定结果：1-任务可通知，2-任务不可通知，3-无法识别是否可通知，4-现场已完成任务需关闭',
    `judge_remark` VARCHAR(1024) DEFAULT NULL COMMENT '判断备注',

    `key_frame_urls` JSON COMMENT '关键帧图片URL列表',

    `recommend_visit_time` DATE DEFAULT NULL COMMENT '最新判定期望上门时间，T+3',

    `gmt_create` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `gmt_modified` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '修改时间',

    PRIMARY KEY (`id`),
    KEY `idx_receive_time` (`receive_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='主材通知任务自动化记录表';
```

## 3. 字段映射

| 上游字段（示例） | 落库字段 | 处理 |
| --- | --- | --- |
| `date` = `"2026-08-10"` | `receive_time` | **T 的时间基准**，解析 `yyyy-MM-dd` → Date（只存日期） |
| `projectOrderId` = `"..."` | `project_order_id` | `Long.parseLong`（纯数字） |
| `materialCode` = `"029001001"` | `material_code` | 直接映射 |
| `materialName` = `"集成吊顶"` | `material_name` | 直接映射 |
| `taskType` = `"09060"` | `task_type` | `Integer.parseInt` → 9060 |
| `taskName` = `"通知复尺"` | `task_name` | 直接映射 |
| （无来源） | `notify_status` | **固定写 1**（未完成通知任务，与列默认值一致） |
| `decisionResult` = `"PASS"` | `judge_result` | 按**我方定义的枚举**映射（见第 4 节）；未知值抛参数错误 |
| `warningLevel` = `"NONE"` | — | **丢弃**，不落库 |
| `remark` = `"所有识别项均通过…"` | `judge_remark` | 直接映射 |
| `items[].keyFrameUrls`（聚合） | `key_frame_urls` | 汇总所有 items 的 keyFrameUrls 成 JSON 数组字符串存入 |
| `items` 其余识别明细（detectType/fusedResult/spaceResults 等） | — | **丢弃** |
| — | `recommend_visit_time` | `= receive_time + 3 天`（T+3） |
| — | `gmt_create` / `gmt_modified` | DB 默认值（CURRENT_TIMESTAMP） |

## 4. 判断结果枚举（我方定义，同步上游）

```java
public enum NotifyJudgeResultEnum {

    CAN_NOTIFY(1, "可通知"),

    CANNOT_NOTIFY(2, "不可通知"),

    CANNOT_JUDGE(3, "无法判断"),

    SITE_COMPLETED(4, "现场已完成，任务需关闭");
}
```

> 说明：取值以**我方定义**为准，同步给上游；上游按此返回。当前示例 `PASS` 对应 `CAN_NOTIFY(1)`，其余取值待上游对齐后补充映射，未知值在服务层抛参数非法异常。

## 6. 逻辑要点

1. **只新增不更新**：每次回调 `insertSelective` 一条新记录，不做 upsert（索引仅 `idx_receive_time`，按接收日期查）。
2. **T+3 计算**：`recommend_visit_time = receive_time + 3 天`（用项目 `DateUtil` / `Calendar` 加天）。
3. **写库路由**：默认走 slave，插库实现参照现有 insert 服务写法（`CallRecordDaoImpl` 未显式 `routeMaster`），实施时验证实际命中 master。
4. **一期仅暂存**：不触发通知、不操作任务状态，仅做接收 + 落库。

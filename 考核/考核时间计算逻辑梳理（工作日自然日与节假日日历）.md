# 考核时间计算逻辑梳理（工作日/自然日与节假日日历）

本文从头梳理 scm-workbench 中"某节点之后/之前 N 个工作日或自然日"这类考核规则的完整实现：配置怎么存、算法怎么算、日历数据从哪来、口径怎么定，以及由此发现的边界缺陷（日历覆盖窗口外的残余盲区等，其中"跨年盲区"已于 2026-11-01 实测修正）。行号对应 2026-11-01 时的工作区代码。

**一句话总纲**：考核时间 = 带符号的天数偏移 + 逐日行走循环 + 位掩码假日判断；日历类型决定基础口径，指标名决定具体跳哪些假；日历数据 RPC 自施工排程系统、Redis 缓存；结果永远钉在"第 N 个有效日的 23:59:59"。

---

## 一、问题定义

考核规则大量使用相对时间表达，例如：

- "接单完成 **之后 3 个自然日** 送达"
- "木作验收 **之前 2 个工作日** 完成下单"（事前考核）
- "下单 **当天** 完成接单"

系统需要把这类规则翻译成一个精确的 deadline 时间戳（考核时间），用于判定"及时/超时"。参与计算的输入共四个：

| 输入 | 来源 |
|---|---|
| 锚点时间（realCompTime） | 外部系统时间轨迹（OFC/工期/主材任务），前序节点的实际或预计时间 |
| 相对关系（timeRef） | 规则配置：之前/之后/当天 |
| 间隔天数（interval/duration） | 规则配置 |
| 日历类型（timeType） | 规则配置：1=自然日、2=工作日 |

## 三、配置层：三个字段 + 一条校验

### 3.1 字段

规则边上的时间算法由三个字段描述（新模型 `ScheduleEdgeRule` 中对应 `timeRef / interval / timeType`）：

| 字段 | 含义 | 取值 |
|---|---|---|
| `timeRef` | 相对关系 | `之前` / `之后` / `当天` |
| `interval` | 偏移天数 | N（BigDecimal） |
| `timeType` | 日历类型 | `1`=自然日（`HolidayService.CALENDAR_DAYS`）、`2`=工作日（`WORK_DAYS`） |

### 3.2 配置约束

`IndicatorComputeRuleService.java:261-263`：**底线规则配了自然日，一城一策个性化规则也必须自然日**（`Validate.isTrue`）。日历类型由全国底线锁死，城市只能个性化间隔天数（且 ≤ 底线），不能通过换口径变相放松红线。

## 四、翻译层：相对关系 → 带符号天数

```java
// :20-31
private static BigDecimal determineInterval(String timeRef, BigDecimal interval) {
    switch (timeRef) {
        case "当天": return new BigDecimal("0");
        case "之前": return interval.multiply(new BigDecimal("-1"));  // 负数=往前推
        case "之后": return interval;                                  // 正数=往后推
        default: throw new RuntimeException("不支持的时间关系: " + timeRef);
    }
}
```

`processTime()`（:13-18）把符号化后的天数、锚点时间、口径 bitmask、日历表一起交给核心算法。唯一会抛异常的翻译错误是配置了三种之外的 timeRef——这是少数"配错会响"的地方。

## 五、算法层核心：逐日行走循环

📍 `scm-workbench-service/.../service/write/engine/meta/RuleUnit.java:63-94`

```java
public static LocalDateTime figureAssessmentTime(LocalDateTime startTime, Integer interval,
                                                 Integer skipBitmask, Map<LocalDateTime, Integer> calendars) {
    if (skipBitmask == null) skipBitmask = 0;                          // ⚠️ null 静默当 0（见 9.2）
    startTime = startTime.withHour(0).withMinute(0).withSecond(0);     // ① 抹零：天粒度计算
    if (interval.equals(0) && isSkipDate(startTime, ...)) interval = 1;// ② "当天"恰逢假日→顺延
    LocalDateTime assessmentTime = startTime;
    if (interval > 0) {                                                // ③ 正向行走（之后）
        while (interval > 0) {
            assessmentTime = assessmentTime.plusDays(1);
            if (isSkipDate(assessmentTime, ...)) continue;             // 假日：跳过但不计数
            interval--;                                                // 有效日：计数-1
        }
    } else {                                                           // ④ 反向行走（之前）
        while (interval < 0) {
            assessmentTime = assessmentTime.plusDays(-1);
            if (isSkipDate(assessmentTime, ...)) continue;
            interval++;
        }
    }
    return assessmentTime.withHour(23).withMinute(59).withSecond(59);  // ⑤ 钉在当天最后一秒
}
```

### 5.1 关键语义（逐条）

1. **不是时间戳加减**。"N 个工作日之后" ≠ `+N×86400秒`，而是一个"走格子"循环：每走一天先问"这天要跳吗"，**跳过日不消耗计数**，只有落在有效日上才 `interval--`。所以结果精确等于"跨过 N 个非假日"。
2. **天粒度**。锚点时间的时分秒被抹掉（①），结果钉在 23:59:59（⑤）。考核 deadline 的业务语义是"这一天结束前完成即可"，小时级精度不存在。
3. **"当天"的假日顺延**（②）。interval=0 且当天是假日 → 自动改 1，顺延到下一个有效日。
4. **正负对称**（③④）。"之前"就是同样的循环往回走，实现"节点前 N 个工作日"的事前考核。
5. **null 口径静默退化**。skipBitmask 为 null 时当 0 处理 → 什么都不跳 → "工作日"退化成纯自然日，无任何报错（见 9.2）。

### 5.2 假日判断：位运算

📍 `RuleUnit.java:96-99`

```java
public static Boolean isSkipDate(LocalDateTime date, Integer skipBitmask, Map<LocalDateTime, Integer> calendars) {
    Integer dateType = calendars.getOrDefault(date, 0);   // 这一天的"节日类型位掩码"
    return (dateType & skipBitmask) > 0;                  // 与任务口径有交集 → 跳过
}
```

- 日历表中每一天有一个 bitmask 值，标记它**同时属于哪些假期类型**（一个周六又逢国庆 = 两个 bit 都置位）；
- 每个考核任务带一个 `skipBitmask` 声明"我要跳过哪些类型"；
- 两者按位与非零即跳过。**一个机制支持了任意多种"节假日口径"的组合**。
- ⚠️ `getOrDefault(date, 0)`：不在日历表里的日期一律当"什么假都不是"——这是覆盖窗口外盲区的本体（见 9.1，✏️ 2026-11-01 修正：常规跨年日期在 4 年覆盖内，不盲）。

### 5.3 逆运算：figureFactDays（报表侧数延期天数）

📍 `RuleUnit.java:101-120`

```java
startTime = startTime.plusDays(1);          // 从锚点次日开始数
```

## 六、口径体系：bitmask 枚举与三档跳过策略

### 6.1 日历类型枚举（外部依赖，已反编译确认）

📍 `com.ke.utopia.construction.enumeration.ConstructionCalendarTypeEnum`，位于依赖 jar
`~/.m2/repository/com/ke/utopia/construction/artisan-construction-base/2.5.4/artisan-construction-base-2.5.4.jar`

构造器字节码确认：**`bitmask = 1 << value`**。完整解码：

| 枚举名 | value | bitmask | 中文描述 |
|---|---|---|---|
| WORK_DAY | 0 | 1 | 工作日 |
| HOLIDAY_DAY | 1 | 2 | 节假日 |
| ADJUST_WORK_DAY | 2 | 4 | 节假日调休为工作日 |
| DOUBLE_CEASE | 3 | 8 | 双休日 |
| NEW_YEAR | 4 | 16 | 春节（公司） |
| LEGAL_NEW_YEAR | 5 | 32 | 法定春节 |
| **NEW_YEAR_EVE** | 6 | 64 | **元旦**（⚠️ 英文名起错，不是除夕） |
| QING_MING | 7 | 128 | 清明 |
| LABOR_DAY | 8 | 256 | 劳动节 |
| DRAGON_BOAT_FESTIVAL | 9 | 512 | 端午 |
| MID_AUTUMN_FESTIVAL | 10 | 1024 | 中秋 |
| NATIONAL_DAY | 11 | 2048 | 国庆 |
| HIGH_SCHOOL_ENTRANCE_EXAM | 12 | 4096 | 中考 |
| COLLEGE_ENTRANCE_EXAM | 13 | 8192 | 高考 |

推论：
- **除夕没有独立枚举**——除夕是否被跳，取决于上游日历有没有给它打"春节/法定春节/节假日"标，属于数据依赖而非代码保证；
- **ADJUST_WORK_DAY（调休上班的周六）不在任何跳过口径里**——调休日被正确当工作日的前提是上游只给它打 ADJUST_WORK_DAY 标、不打 DOUBLE_CEASE 标，又一个数据契约；
- `HolidayService` 里用 `+` 拼 bitmask（不是 `|`），因各枚举 bit 互不重叠而恰好正确——"约定正确"而非"类型正确"。

### 6.3 口径全景对比（重点认知）

| 口径 | 春节 | 国庆 | 中高考 | 元旦/清明/五一/端午/中秋 | **普通双休** | 使用方 |
|---|---|---|---|---|---|---|
| 自然日 | ✅跳 | ❌算 | ❌算 | ❌算 | ❌**算** | timeType=1 的所有规则 |
| 工作日-常规 | ✅跳 | ✅跳 | ✅跳 | ❌**算** | ❌**算** | 八合一：下单/接单/备货/入仓/报价/签收等 |
| 工作日-特殊 | ✅跳 | ✅跳 | ✅跳 | ✅跳 | ✅跳 | 八合一仅"送达及时"；排程模型常规任务 |
| 排程-特殊 | ✅跳 | ✅跳 | ✅跳 | ❌算 | ❌算 | 排程模型仅"备货" |

两个反直觉结论：

1. **"自然日"不是纯自然日**——它跳春节。业务原因：春节全行业停摆 2~4 周（工厂放假、物流停运、班组返乡），不豁免会产生批量"假超时"，考核失去公信力。自然日的真实定位是"最严口径 + 春节法定免责"。
2. **"工作日"大多不跳双休**——八合一常规口径的真实语义是"非长假日"，普通周六周日照常计数（内部人员/供应商周末可作业）；只有"送达及时"（物流上门、工地收货，周末真没人）享受双休豁免。排程模型反过来：常规任务全跳双休，唯独"备货"不跳（工厂可周末备货）。

每一档差异都有业务逻辑支撑（谁在干活、哪天真的干不了），但**全部硬编码，配置界面上的"工作日"三个字背后是哪一档，运营不可见**。

要点：

## 八、完整计算示例

### 8.1 正向（之后 + 工作日特殊口径）

> 规则："接单完成 之后 3 个工作日 送达"（送达 = SPECIAL：跳双休+全部节日）
> 锚点：接单完成 = 周五 14:30

1. 抹零 → 周五 00:00；interval=+3
2. 行走：周六（跳）→ 周日（跳）→ 周一（3→2）→ 周二（2→1）→ 周三（1→0）
3. 结果 = **周三 23:59:59** = 送达考核 deadline

同规则若配"自然日 3 天"：只跳春节 → 周五+3 = **周一 23:59:59**。

### 8.2 反向（之前 + 事前考核）

> 规则："木作验收 之前 2 个工作日 下单"，锚点 = 验收预计时间（周一）

1. interval=-2，从周一往回走
2. 周日（跳）→ 周六（跳）→ 周五（-2→-1）→ 周四（-1→0）
3. 结果 = **周四 23:59:59** = 最晚下单 deadline

锚点用预计时间即可在工程未开工时算出 deadline——事前考核的实现基础。

### 8.3 当天 + 假日顺延

> 规则："下单 当天 接单"，锚点 = 周六（双休口径）

interval=0 且当天是跳过日 → 自动改 1 → 顺延至下周一 23:59:59。

## 九、边界缺陷清单（本文核心产出）

### 9.1 日历覆盖窗口与残余盲区（✏️ 2026-11-01 重要修正：原"跨年日历盲区"不成立）

**修正事实**：上游 `getCalendar(year)`（`ConstructionScheduleRpcService:128`）虽然只传当年，但**实际返回 year-2 ~ year+1 共 4 年**日历数据；workbench 侧（`ConstructionScheduleService.java:128-135`）不按年过滤、原样入 map。缓存 key `{year-2}{year}{year+1}_holiday_` 名实相符，`year-2` 不是笔误而是覆盖下界。

**由此作废的原结论**（均基于"日历只覆盖当年"的错误前提）：

- ~~四情形 1/2/4：12 月正向走进 1 月、1 月反向回退 12 月、跨年重算结果翻转~~——这些日期都在 4 年窗口内，查得到、跳得对；
- ~~"1 月重算会把 12-24 锚点的正确结果改坏"反例~~——不成立，窗口内重算幂等成立，"1 月重算没问题"的直觉是对的；

## 十三、汇报用一段话

> 考核系统的"N 个工作日/自然日"不是简单加减天数，而是一个逐日行走循环：每天问一次日历"这天跳不跳"，跳过日不计数；日历是施工排程系统统一维护的类型位掩码表，"自然日/工作日"两档口径叠加指标名注册表，实际形成四档跳过策略——"自然日"其实跳春节，多数"工作日"其实不跳双休。日历 RPC 虽只传当年，但上游返回的是 year-2 ~ year+1 共 4 年数据，常规跨年场景不盲（走读中曾据"单年覆盖"前提推断出跨年盲区，经实测修正——教训是跨系统契约必须实测，不能只读本侧代码）。残余风险收敛为两个：一是锚点超出 4 年覆盖窗口时，行走区间仍被静默当工作日计数，且 year+1 段数据新鲜度依赖上游打标节奏（明年节假日安排通常 11~12 月才公布）；二是新指标不在硬编码注册表里时，工作日口径退化成纯自然日（有 error 日志但不阻断，错误结果照写照广播）。两者都不阻断计算、配置界面不可见，也正是 AI 配置 check 该覆盖的首批规则。

| B4 🆕 | **缓存解析失败无回退**：缓存 JSON 损坏 → `jsonStr2Obj` 抛异常，不回退 RPC 重拉；并发删 key 后多计算同时重建无锁（后果轻，RPC 幂等） | HolidayService:149-151 | 单点脏缓存放大 |
| B5 ✏️ | 跨年夜毫秒竞态：`now().getYear()` 调两次，可能把 N 年日历存进 N+1 年 key——4 年覆盖下 N 年版本身含 N+1 年数据，危害降级为"key 与数据年份错位" | HolidayService:144/148 | 极低概率且影响有限 |

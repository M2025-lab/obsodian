# 04. IndicatorScheduleDAGService#getBaseEventsBySchedule —— 重算范围圈定

> 位置：`IndicatorScheduleDAGService.java:878`（`getBaseEventsBySchedule`）；`:920`（`getNodesBeforeContract`）

## 一、功能是什么

把「这次要重算什么」从三个业务口径翻译成 DAG 节点集合，输出 `FigureScheduleParam{startNodes, extNodes}`：

- **startNodes**（DFS 正向遍历起点）：后门链路包含 ① 全部工期类事件节点（`constructionDiff=true`）② 有 diff 的基装包事件节点；
- **extNodes**（额外补算节点，不作为遍历起点）：签前节点（`beforeContract=true`，即设计/测量/复尺/下单这些签约前的节点）。

startNodes 会作为 [[08.IndicatorScheduleDAGService-getFigureNodeList|getFigureNodeList]] 的 DFS 起点，沿边找出全部下游待计算节点；extNodes 则直接并入计算列表补算。

## 二、逻辑实现

```java
public FigureScheduleParam getBaseEventsBySchedule(String projectOrderId, Boolean constructionDiff, Boolean beforeContract, Set<String> basicNodeCodeSet) {
    ScheduleDAG indicatorDAG = getScheduleDAG(projectOrderId);      // 拿（或建）DAG
    if (Objects.isNull(indicatorDAG) || isEmpty(indicatorDAG.getScheduleEventNodes())) return null;  // 未配规则 → 静默跳过

    // ① 工期节点全部作为 startNode
    if (constructionDiff) {
        res.getStartNodes().addAll(eventNodeList.stream()
                .filter(n -> n.getEventType().equals(EventTypeEnum.CONSTRUCTION_SCHEDULE.getValue())).collect(...));
    }
    // ② 签前节点 → extNodes
    if (beforeContract) {
        Set<String> extCodeSet = getNodesBeforeContract(projectOrderId);
        res.getExtNodes().addAll(eventNodeList.stream().filter(n -> extCodeSet.contains(n.getUniqCode())).collect(...));
    }
    // ③ 基装包 diff 节点 → startNodes（匹配 scheduleCode_categoryId）
    if (CollectionUtils.isNotEmpty(basicNodeCodeSet)) {
        res.getStartNodes().addAll(eventNodeList.stream()
                .filter(n -> n.getEventType().equals(EventTypeEnum.BASIC_PACKAGE_SCHEDULE.getValue()))
                .filter(n -> basicNodeCodeSet.contains(String.format("%s_%s", n.getScheduleCode(), n.getCategoryId())))
                .collect(...));
    }
    return res;
}
```

**`getNodesBeforeContract`（:920）子逻辑**：找「实际完成时间还填不上（estimatedTime 早于哨兵 2000-01-01）」的签前任务：

1. 从 starlord 拉四类任务详情（设计/测量/复尺/下单，`taskTypeIn=[DESIGN, MEASURE, RECHECK_SCALE, ORDER]`）；
2. 跳过重启任务（`restartCount != 0`）；
3. 对每个任务节点，若 `estimatedTime < 2000-01-01`（即预估时间从未配置/未计算），把 `materialCode_eventCode` 加进 extCodeSet —— 这些是「签了合同但当时没算出结果」的节点，本轮补算。

## 五、备注

- **后门参数组合 `(true, true, basicNodeCodeSet)` 的效果**：startNodes = 全部工期节点 + 全部 diff 基装包节点 → DFS 下游覆盖几乎整个 DAG 的工期侧；extNodes = 签前未出结果节点。基本等于「项目级全量」。
- `return null` 的场景（未配置排程规则模板）由 Controller 侧静默跳过（`scheduleParam != null` 判断），不报错。刷数时若某项目怎么都不出数，先怀疑这里：项目没有排程模板版本。
- 基装包节点匹配键是 `scheduleCode + "_" + categoryId`，而 [[03.IndicatorScheduleDAGService-checkBasicDiff|checkBasicDiff]] 返回的是裸 `nodeCode`（= taskType）。能对上是因为基装包 DAG 节点的 `scheduleCode` 就是 taskType（`base_xxx`），`categoryId` 是施工包 ID（nodeCode 去掉 taskType 前缀）。手工造 basicNodeCodeSet 刷数时注意必须带 `_施工包ID` 后缀，否则匹配不到。
- 兄弟方法 `getBaseEventsByActionType`（货单动作触发）与 `getBaseEventsByDispatch`（用工节点触发）服务于正式事件链路，后门不经过，此处不展开（结构同构：都是「命中节点做 startNode + 相关节点做 extNode」）。

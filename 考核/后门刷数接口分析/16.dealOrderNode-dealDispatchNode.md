# 16. dealOrderNode / dealDispatchNode —— 载体级计算、落库与外发

## 一、功能是什么

两个方法同构（一个走货单载体、一个走用工载体），是「单个载体实例」的完整闭环：**算 → 调汰换 → 回写轨迹 → 落库 → 外发**。这是整条后门链路所有**写动作**的发生地。

## 二、逻辑实现

### dealOrderNode（货单载体）

```java
FigureRes figureRes = figureNode(ruleList, orderNode, null, ...);        // 1) 算（见17号文档）
if (figureRes.figureTime == null) return;                                // 算不出（无规则/无前置数据）→ 静默结束
if (orderNode.replacement) {                                             // 2) 汰换调整
    adjustExpectTimeForReplacement(orderNode.replaceDate, figureTime, calendars); // 考核时间 = max(计算值, 汰换时间+N自然日)
    syncBaseEvalResult(figureRes);                                       //    调整后的时间同步回 baseEvalResult 结构体
}
updateAssessmentTimeInTrack(nodeTimeTrackMap[figureNode.uniqCode], ...); // 3) 把考核时间写回轨迹（级联：本轮后续节点用它当前置）

boolean update = false;
if (taskType == PLACE_ORDER) {                                           // 4a) 下单指标落库三连
    baseEvalSDOS = evalOrderService.mergeIndicator(旧baseEvalResult, 新结果);
    updateProjectOrder(projectOrder, baseEvalSDOS);                      //    → indicator_project_order
    update = updateFulfillmentTask(...);                                 //    → fulfillment_task（考核起止时间）
    updateIndicatorOrder(projectOrder, figureRes.baseEvalResult, ...);   //    → indicator_order（下单及时同步到货单）
} else {                                                                 // 4b) 其余货单指标落库两连
    baseEvalSDOS = mergeIndicator(...);
    updateOrder(order, baseEvalSDOS);                                    //    → indicator_order
    update = updateFulfillmentTask(orderNo, ...);
    if (update && syncMaterialTask && taskType == DELIVERY_GOODS) {      //    送达指标额外：发 Spring 事件
        applicationEventPublisher.publishEvent(IndicatorChangedEvent);   //    → IndicatorChangedListener（同步供应商）
    }
}
if (update && syncMaterialTask) {                                        // 5) 异步回写 starlord 主材任务
    rpcAsyncExecutor.execute(() -> syncMaterialTaskService.syncAssessmentTime(orderNode, null, expectTime));
}
sendAssessmentMessage(orderNode, null, expectStartTime, expectTime);     // 6) 同步考核时间到排程（Kafka）
```

### dealDispatchNode（用工载体）

```java
figureRes = figureNode(ruleList, null, dispatchNode, ...);               // 1) 算
if (figureTime == null) return;
if (dispatchNode.replacement) { adjustExpectTimeForReplacement; syncBaseEvalResult; }
updateAssessmentTimeInTrack(...);
boolean update = updateDispatch(dispatchNode, figureRes);                // 2) → indicator_task_dispatch_node（有则update无则insert）
if (update && (syncMaterialTask || dispatchNode.mode == DELIVERY_FLOW)) // 3) mode=7 强制同步（历史脏数据兜底）
    rpcAsyncExecutor.execute(() -> syncAssessmentTime(null, dispatchNode, expectTime));
sendAssessmentMessage(null, dispatchNode, ...);                          // 4) Kafka 同步排程
```

### 关键子方法

- **`updateFulfillmentTask`（:963）**：按 `projectCode+taskType+categoryId+deliveryId(+orderNo)+状态≠取消+返补标记` 查 fulfillment_task，**剔除考核时间完全没变的**（避免无效 update），再按 idIn 批量 update `assessmentStartTime/assessmentEndTime/assessmentType`。返回是否真的更新了。
- **`updateProjectOrder` / `updateOrder`（:955/:1091）**：序列化 baseEvalSDOS 为 JSON，**与库里 baseEvalResult 字符串比对**，不同才 updateByPrimaryKeySelective——幂等保护。
- **`updateIndicatorOrder`（:1002）**：把 project_order 算出的「下单及时」指标同步到同项目同品类同区域(qvyv)同履约的**非返补** indicator_order 行（复用 scheduleAllNode.orderMap 里的 DB 实例改库，防止覆盖其他指标的并发修改）。
- **`updateDispatch`（:1099）**：按 `nodeId` 查 indicator_task_dispatch_node；不存在则 insert 全字段（含 evalResult JSON），存在则 update 考核三字段+evalResult。
- **`adjustExpectTimeForReplacement`（:319）**：`考核时间 = max(计算考核时间, 汰换时间 + N自然日)`，N=Apollo `replace.supplier.assessment.buffer.days`（默认3）；触发调整时 expectStartTime 也同步改为汰换时间。给被汰换供应商留缓冲。
- **`sendAssessmentMessage`（:1134）**：组装 `AssessmentTimeChangePayload`（货单分支用 `fulfillmentTaskToMaterialTaskType` 映射 taskType/nodeType；用工分支带 dispatchId/nodeId/restartCount），交给 ConstructionScheduleService。

## 四、下钻终点

- 〔DB〕`indicator_project_order`（update baseEvalResult）；`indicator_order`（update baseEvalResult，下单及时同步）；`fulfillment_task`（select + updateByExample 考核三字段）；`indicator_task_dispatch_node`（selectOne + insert/update）

## 五、备注

- **落库幂等三层保护**：baseEvalResult JSON 比对（order/project_order）、考核时间全等剔除（fulfillment_task）、update 返回值（dispatch）。所以后门重刷安全，但**外发不幂等**——`sendAssessmentMessage` 无条件发送（不看 update 标志），重复刷数会给排程发重复消息；`IndicatorChangedEvent` 只在 update=true 时发（送达指标）。
- `syncMaterialTask` 开关贯穿货单/用工两分支，但用工分支多了 `mode==DELIVERY_FLOW(7)` 的强制条件——注释说明：历史上有未进排程的项目存在 mode=7 脏数据，靠这里同步。
- 下单指标的特殊性：下单载体在 indicator_project_order，但结果要**双向落**（project_order 的 baseEvalResult + 同步到 indicator_order 各货单行）；「下单及时」指标名在两处共享。
- `updateFulfillmentTask` 只 update **非取消**任务，且返补/正常单按 flowType 区分 criteria——刷数后发现某货单指标没更新，先查它是不是返补单或已取消。

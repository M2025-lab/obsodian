# 15. HolidayService —— 节假日日历服务

## 一、功能是什么

提供「日期 → 假期类型 bitmask」的日历（覆盖 year-2 ~ year+1 共四年），是考核时间推算（[[19.TimeProcessor-processTime]]）的跳假期依据。同时维护**指标名 → 跳过哪些假期**的静态映射（自然日/工作日两套口径）。

## 二、逻辑实现

### getRecentCalendar（:157）

```java
String redisKey = "{lastYear}{year}{nextYear}_holiday_";     // 例 2024202520262027_holiday_（带前缀生成）
if (redis 存在) dateMap = JSON 反序列化;
else dateMap = constructionScheduleService.queryCalendarByYear(year);   // RPC 拉当年日历
redisClient.set(redisKey, JSON, 60*60);                       // 写回，TTL 1小时
return {date("yyyy-MM-dd 00:00:00") → bitmask};
```

### bitmask 体系（静态常量）

| 常量 | 跳过范围 | 用途 |
|---|---|---|
| `CALENDAR_DAY_BITMASK` | 公司春节+法定春节 | **自然日口径**（大多数指标）：仅春节顺延 |
| `SCHEDULE_NORMAL_BITMASK` | 全部节日+双休+中考+高考 | **排程工作日口径**（常规排程指标） |
| `SCHEDULE_SPECIAL_BITMASK` | 公司春节+十一+中考+高考 | 排程特殊任务（**备货**） |
| `ORIGIN_NORMAL/SPECIAL_BITMASK` | 同上两档 | 旧八合一考核指标（旧链路用） |

静态块 `indicatorHolidayMap` 登记**每个指标名**用哪档 bitmask（40+ 个排程指标 + 11 个旧八合一指标）。`figureCore` 遇到工作日型规则时按指标名查这个 map。

### 辅助方法

- `deleteHolidayCache()` / `getHolidayCache()`——运维后门：清/看当年日历缓存（日历数据修正后要先清再刷数）。
- `figureAssessmentTime(startTime, interval, skipBitmask)`——单点计算接口（ToolController 暴露的验算工具用）。

## 四、下钻终点

- 〔Redis〕`{2024}{2025}{2026}{2027}_holiday_`（4 年拼接 key，TTL 3600s）

- 〔纯函数〕bitmask 位运算与静态映射表

## 五、备注

- **缓存只存「当年」拉取的结果**，但 key 名含 4 个年份——实际覆盖范围取决于排程 RPC 返回的日历范围（key 只是命名习惯）。跨年刷数（算到去年/明年节点）时若 RPC 只给当年，边界日期会缺失 → `figureAssessmentTime` 遇到 map 里没有的日期按非假期处理。
- `queryCalendarByYear` 的 bitmask 汇总逻辑：一天多类型（法定假+公司假）按位求和，`skipBitmask` 与运算非零即跳过。
- **日历改版流程**：排程侧改日历 → 调 `/` 后门清 holiday 缓存（deleteHolidayCache）→ 等待或强制重算。1 小时 TTL 内旧日历仍在生效。
- `indicatorHolidayMap` 缺新指标名时 `figureCore` 打 ERROR 且 NPE（17 号文档备注）——新增排程指标三件套：EVENT_ENTITY 字典 + indicatorHolidayMap + ScheduleEventNameEnum，缺一不可。

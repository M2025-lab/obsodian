# 09. IndicatorScheduleDAGService#getDataNodeList —— 圈数据节点

## 一、功能是什么

对每个**待计算节点**（figureNode）反向看它的入边：如果某条入边的规则能匹配上本项目载体（即这条规则真的会参与计算），那么该入边的**前置节点**就是「需要拉时间轨迹的数据节点」。返回数据节点集合，供 [[12.EvalScheduleOrderService-getScheduleTimeTrack|getScheduleTimeTrack]] 拉取轨迹。

一句话：figureNodeList 回答「算谁」，dataNodeList 回答「算它们要用谁的数」。

## 二、逻辑实现

```java
public List<ScheduleEventNode> getDataNodeList(List<ScheduleEventNode> fugureNodeList, ScheduleAllNode scheduleAllNode) {
    Set<ScheduleEventNode> dataNodeSet = new HashSet<>();
    for (ScheduleEventNode node : fugureNodeList) {
        ScheduleOrderDispatchNode scheduleOrderDispatchNode = getOrderDispatchNode(node, scheduleAllNode); // 节点上挂的载体
        for (ScheduleNodeEdge edge : node.getEdgeInList()) {          // 每条入边
            if (hasFilterNode(edge.getRuleList(), scheduleOrderDispatchNode)) {  // 规则匹配载体
                dataNodeSet.add(edge.getNodeFrom());                 // 前置节点要拉数据
                dataNodeSet.add(node);                               // 自身也要拉——实际完成时间要写进考核结果
            }
        }
    }
    return new ArrayList<>(dataNodeSet);
}
```

注意第二个 add：**figureNode 自身也在数据集里**。原因（代码注释原话）：「验证通过的话，figureNode 自身也需要获取时间，因为实际完成时间需要写到考核结果中」——考核结果里的 realCompTime 就来自自身轨迹的 completeTime。

## 三、调用了谁 / 为什么

| 被调方法 | 为什么调用 | 一句话简介 |
|---|---|---|
| `getOrderDispatchNode`（[[08.IndicatorScheduleDAGService-getFigureNodeList\|08 号文档]]内详解） | 拿节点挂载的项目载体 | 按 EVENT_ENTITY 字典取 order/dispatch 载体集合 |
| `hasFilterNode`（[[08.IndicatorScheduleDAGService-getFigureNodeList\|08 号文档]]内详解） | 判定「这条边的规则对本项目生效」 | 载体×规则匹配（品类/供应商/履约/重启） |

两个工具方法与正向 DFS 是同一套——正向用来「走」，反向用来「收」，匹配语义完全一致，保证算的节点和拉的数据节点自洽。

## 四、下钻终点

无独立 IO——纯集合运算，复用 [[08.IndicatorScheduleDAGService-getFigureNodeList|08]] 已装载的载体（**重要：调用本方法前 scheduleAllNode 必须已装载**，即 getFigureNodeList 必须先执行）。

## 五、备注

- `hasFilterNode` 只用**边的规则**比对**目标节点（node）**的载体——`getOrderDispatchNode(node)` 取的是 node 自己的载体，不是 edge.nodeFrom 的。语义是「node 这个事件上挂的实例，是否满足边上规则的品类/供应商条件」；满足则该规则生效，其前置 nodeFrom 需要轨迹。
- 数据节点用 `HashSet<ScheduleEventNode>` 去重——ScheduleEventNode 未重写 hashCode 时按引用去重；由于 DAG 节点对象在本次 getScheduleDAG 中是单例引用（nodeMap 重建过），引用相等即同一节点，行为正确。
- dataNodeList 里可能包含不在 figureNodeList 中的节点（纯前置、自身不算）——它们只提供时间，不产出指标。

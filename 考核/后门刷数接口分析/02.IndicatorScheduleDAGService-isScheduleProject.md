# 02. IndicatorScheduleDAGService#isScheduleProject —— 排程考核白名单判断

> 位置：`IndicatorScheduleDAGService.java:1008`

## 一、功能是什么

判断某个项目订单是否被**显式配置**进排程材料考核体系（白名单）。返回 `boolean`：`schedule_project` 表里存在该 `projectOrderId` 记录即为 true。

它回答的问题是：「这个项目要不要走新排程考核（而非旧全国货单考核）」。在后门接口中与 starlord 排程开关构成「或」关系（见 [[01.ToolController-refreshEvalScheduleProjectOrder]]）。

## 二、逻辑实现

```java
public boolean isScheduleProject(String projectOrderId) {
    ScheduleProjectExample example = new ScheduleProjectExample();
    example.createCriteria().andProjectOrderIdEqualTo(projectOrderId);
    ScheduleProject exist = scheduleProjectMapper.selectOneByExample(example);
    return exist != null;
}
```

就是一次按 `project_order_id` 的单表等值查询，存在即命中。没有缓存、没有开关，表就是唯一事实源。

## 三、调用了谁 / 为什么

| 被调方法 | 为什么调用 | 一句话简介 |
|---|---|---|
| `scheduleProjectMapper.selectOneByExample` | 唯一的数据来源 | MyBatis 生成的按条件查单条 mapper |

无其他方法调用——叶子方法。

## 四、下钻终点

- 〔DB〕`schedule_project` 表，查询条件 `project_order_id = ?`，取任意一条（`selectOneByExample`）。该表是排程考核灰度白名单：谁配了谁走新考核。写入方不在这条链路上（由配置/运营侧维护）。

## 五、备注

- 注意与 [[10.EdarStarlordRpc|queryProjectInScheduleSwitch]] 的分工：白名单 = workbench 本地强控（适合灰度放量）；排程开关 = starlord 业务事实（项目真实排程状态）。两者命中任一即重算，白名单数据脏了只会「多算」，不会漏算。
- `selectOneByExample` 在多条命中时行为取决于 MySQL 返回序，但该表语义上一个项目至多一条，无实际风险。

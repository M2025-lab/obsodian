# 00. 总览：后门刷数接口 /api/refresh/eval/schedule/projectOrder

> **一句话功能**：新排程考核的「项目级重算后门」——传入一批 `projectOrderIds`，绕过 Kafka 事件触发，把每个项目的排程考核指标（下单/接单/备货/送达/签收/测量/设计/复尺/安装/打磨/结晶…）从零完整重算一遍并落库、同步下游。
> **代码位置**：`scm-workbench-start` 模块 `ToolController#refreshEvalScheduleProjectOrder`（ToolController.java:230）。
> **本文件夹组织方式**：A 方法调用 B、C，就为 A 建一篇文档（介绍 A 的逻辑/功能/为什么调 B、C，并一句话简介 B、C），再按同样结构为 B、C 各建文档，如此递归，直到 RPC / DB / Redis / Kafka / 纯函数叶子。

## 接口定位

| 项 | 值 |
|---|---|
| HTTP | `POST /api/refresh/eval/schedule/projectOrder` |
| 入参 | `RequestBody List<String> projectOrderIds`（项目订单 ID 列表） |
| 返回 | `ResultDTO<Void>`（恒 success；单项目失败抛 `ServiceException`，code=RPC_CALL_FAILURE，文案「排程考核后门计算失败」） |
| 所属 Controller | `ToolController`（工具/后门接口集合，无鉴权逻辑，靠运维入口控制） |
| 与正式链路关系 | 正式链路 = Kafka 事件 → Listener → 相同的 Service 方法；本接口复用同一套计算服务，只是入口换成手工 HTTP 调用 |
| 兄弟接口 | `/api/refresh/eval/projectOrder`（旧全国货单考核重算，走 `EvalOrderService`，不在本文件夹范围） |

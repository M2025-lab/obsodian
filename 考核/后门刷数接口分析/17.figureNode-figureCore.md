# 17. figureNode / figureCore —— 单载体考核时间计算核心

## 一、功能是什么

`figureNode` 是入口：对一个载体（货单或用工）+ 一个事件节点，产出 `FigureRes{figureTime 应开始/应完成时间线, baseEvalResult 考核结果结构体}`。`figureCore` 是内核：规则分组 → 每组按前置轨迹推时间 → 多组结果取最早/最晚。

## 二、逻辑实现

### figureNode（:350）——细过滤 + 调内核 + 装结果

```java
List<ScheduleEdgeRule> orderRules = filterRuleByOrderNode(ruleList, orderNode, dispatchNode); // 细过滤
if (orderRules.isEmpty()) return 空Res;                    // 该载体没有适用规则
CalculatedTimeline evalTime = figureCore(orderRules, nodeTimeTrackMap, orderNode, dispatchNode, figureNode, calendars);
if (evalTime == null) return 空Res;                        // 前置数据不足
IndicatorEvalSDO evalResult = createIndicatorEvalSDO(...); // 时间线 → 固定结构体（见下）
return FigureRes{baseEvalResult: evalResult, figureTime: evalTime};
```

**`filterRuleByOrderNode`（:593）细过滤**——在 14 号文档粗过滤基础上按**载体自身**全匹配：

| 条件 | 含义 |
|---|---|
| `r.indicatorName == 载体事件名` | 货单用 ORDER_EVENT_NAME[taskType]、用工用 DISPATCH_EVENT_NAME[taskType_nodeType] 反查事件名 |
| `r.categoryId == 载体品类` | 品类精确 |
| `r.deliveryType == -1 或 == 载体履约方式` | 履约（仓库/直送/代销…） |
| `r.deliveryId == "-1" 或 == 载体供应商` | 供应商（-1 不限） |
| `r.restart == 载体是否重启` | 用工载体 restartCount>0 才配重启规则 |
| `r.replenish == 载体是否返补` | 返补单只配返补规则 |

### figureCore（:375）——三段式

**① 按 ruleId 分组并排序**（取最精确的一组）：
```java
sortedGroups = rules.groupBy(ruleId).sorted(
    deliveryType 降序(nullsLast) then deliveryId 降序(nullsLast));
usedRules = sortedGroups.get(0);          // 只用第一组：履约方式最具体(-1最泛)优先，供应商同理
funcName = usedRules[0].funcName;         // "最早"/"最晚"
ruleMap = usedRules.groupBy(indexId);     // 同 ruleId 下按 divide 分段
```

**② 每个 indexId 段算一条时间线**（`calculateTimelines` 详 [[18.calculateTimelines-filterTimeInfos|18 号文档]]）：
```java
for (entry : ruleMap) {
    calculateTime = calculateTimelines(edgeRules, nodeTimeTrackMap, relateNodeId, supplierId, orderNo, dispatchId, restartCount, orderFigure);
    // 前置时间 startTime + 关系(之前/之后/当天) + 间隔 → 应开始时间
    skipBitmask = 工作日规则 ? indicatorHolidayMap[figureNode.name] : CALENDAR_DAY_BITMASK;   // 节假日口径选择
    expectStartTime = TimeProcessor.processTime(timeRef, interval, calculateTime.startTime, skipBitmask, calendars);
    // 任务耗时段：若载体 innerInterval>0 且实际已开始(factStartTime!=null)，用实际开始时间推
    startTime = (innerInterval>0 && factStartTime!=null) ? factStartTime : expectStartTime;
    expectEndTime = TimeProcessor.processTime("之后", innerInterval, startTime, skipBitmask, calendars);
    calculatedTimelines.add({expectStartTime, expectTime, ...});
}
```

**③ 多段择一**：`evalTime = evalOrderService.selectFinalTimeline(funcName, calculatedTimelines)`——「最早」取 expectTime 最小者，「最晚」取最大者。`realFlag` = 全部段都是实际时间(realFlag=1) 才为 1。

### createIndicatorEvalSDO（:875）——结果结构体

填 indicatorName/expectStartTime/expectCompTime/interval/assessDayType/startTime/前置节点链 codeFromList+codeTo（`RuleUnit.getRealNode` 剥品类前缀得到人话节点名）；**realCompTime 从自身轨迹找**：按 orderNo（货单）或 dispatchId+restartCount+nodeId（用工）匹配 TimeInfo 取 completeTime；最后 evaluation = realCompTime > expectCompTime ? 1 : 0（超期）。

## 五、备注

- **ruleId 分组排序的语义**：`deliveryType/deliveryId` 都是「-1=不限」，降序排序让具体值（非-1）排前——**载体匹配到的最具体规则赢**。这就是规则模板里「通用兜底 + 特殊覆盖」的实现机制。
- 工作日口径查 `indicatorHolidayMap` 拿不到会打 ERROR 日志（「processRules计算出现不识别的indicatorName」）并 NPE——新增指标名必须同步登记 HolidayService 的 static 块。
- `realFlag` 的构成：`ruleMap.size() == calculatedTimelines.size() && 全部 real` —— 有一段算不出就整体 realFlag=0（部分依赖预估时间，结果不算「全实际」）。评估刷数结果可信度时可参考。
- 下单指标用 `relateNodeId`（指向复尺任务）实现「下单及时以下单任务关联的复尺为前置」——见 12 号文档 `initInnerIntervalAndRelateNodeId` 的回填。

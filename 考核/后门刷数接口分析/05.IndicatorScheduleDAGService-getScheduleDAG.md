# 05. IndicatorScheduleDAGService#getScheduleDAG —— 取/建排程考核 DAG

## 一、功能是什么

获取某项目的**排程考核 DAG**（`ScheduleDAG`：事件节点集 + 边规则集 + nodeMap/edgeMap）。DAG 是排程考核的「骨架」——把排程规则模板翻译成「谁依赖谁、按什么规则算」的图。本方法负责：

1. 拿项目对应的规则模板版本号（排程系统）；
2. 按 version 查 Guava 本地缓存，miss 则调 `rebuild` 全量建图；
3. 无论缓存命中与否，**每次都重建边/节点的对象引用**（因为缓存反序列化是深拷贝，`nodeFrom/nodeTo` 引用关系丢失）。

## 二、逻辑实现

```java
public ScheduleDAG getScheduleDAG(String projectOrderId) {
    Long version = constructionScheduleRpcService.getIndicatorVersion(projectOrderId); // RPC 拿模板版本
    if (version == null) { LOGGER.info("无法构建考核DAG, ...未配置排程规则"); return null; }
    String cacheString = SCHEDULE_DAG_CACHE.getIfPresent(version.toString());
    ScheduleDAG res = StringUtils.isBlank(cacheString)
            ? rebuild(version)                                             // 缓存 miss → 全量建图
            : JsonUtil.jsonStr2Obj(cacheString, ScheduleDAG.class);        // 缓存命中 → 反序列化
    // ↓ 下面这段每次执行（缓存命中也要做）：重建运行时引用
    res.setScheduleEdgeMap(new HashMap<>());
    res.setScheduleNodeMap(...toMap(ScheduleEventNode::getUniqCode));
    for (ScheduleEdgeRule edgeRule : res.getScheduleEdgeRules()) {        // 每条规则建立 nodeFrom→nodeTo 的边
        for (String codeFrom : edgeRule.getCodeFromList()) {
            // 找不到节点就跳过并记日志
            String edgeKey = codeFrom + "," + edgeRule.getCodeTo();
            if (edgeMap 不含 edgeKey) {
                建 ScheduleNodeEdge{nodeFrom, nodeTo, ruleList};
                nodeFrom.getEdgeOutList().add(edge); nodeTo.getEdgeInList().add(edge); // 维护入度出度
            }
            edgeMap.get(edgeKey).getRuleList().add(edgeRule);
        }
    }
    // 过滤掉入度出度全为 0 的孤立节点（不参与任何规则）
    res.setScheduleEventNodes(...filter(入度或出度非空));
    res.setScheduleNodeMap(重建);
    return res;
}
```

要点：

- **缓存键是 version 不是 projectOrderId**：同一模板版本的所有项目共享一张 DAG 结构（规则是模板级的），项目个性化只体现在「节点上挂了哪些任务载体」（那是在 [[08.IndicatorScheduleDAGService-getFigureNodeList|getFigureNodeList]] 阶段按项目数据过滤的）。
- **缓存失效**：`SCHEDULE_DAG_CACHE` 是 Guava `expireAfterAccess(10min), maximumSize(100)`，即最多缓存 100 个版本，10 分钟无访问过期。另有手工失效入口 `removeScheduleDAGCache(projectOrderId)`（ToolController `/api/remove/schedule/dag/cache`）：查当前 version 后 `invalidate(version)`，**排程模板规则改了要刷数前先调它**，否则 10 分钟内还是旧规则。
- **规则改了但没清缓存的后果**：DAG 里还是旧边旧规则 → 重算结果按旧规则出。这是刷数 SOP 的经典坑。

## 五、备注

- **性能特征**：每次 `getScheduleDAG` 必发一次 version RPC（无缓存）；建图结果按 version 缓存 10 分钟，所以同一项目连续重算能吃到缓存。
- 返回 null 的唯一场景是 version == null（项目未绑模板）。日志「无法构建考核DAG, projectOrderId={} 未配置排程规则」可直接定位。
- 边规则里 `codeFromList` 是「多对一」结构：一条考核规则（ruleId）允许多个前置节点（同 indexId 的多个 ruleCfg 行），每个 codeFrom 都挂到同一个 edge 的 ruleList 上——这就是「前置条件任一满足即可」的实现基础。

# 14. EvalScheduleOrderService#doScheduleEval —— 逐节点计算调度

## 一、功能是什么

数据齐了开始算数：遍历每个**待计算节点**（figureNode），按节点上的载体类型分流——

- 节点名在 `EVENT_ENTITY` 字典里且载体类型是 **货单（ORDER_NODE=0）**：对每个挂载的货单载体调 `dealOrderNode`；
- 载体类型是 **用工（DISPATCH_NODE=1）**：对每个挂载的用工载体调 `dealDispatchNode`（还要 nodeType 对得上字典第三位）；
- 名字不在字典里的节点（工期节点、基装包节点、跨品类前置等）**跳过**——它们只做前置数据，不产出指标。

## 二、逻辑实现

```java
public void doScheduleEval(figureNodeList, nodeTrackList, scheduleAllNode, syncMaterialTask) {
    Map<String, NodeTimeTrackV2> nodeTimeTrackMap = ...toMap(getCode);       // 轨迹按 code 索引
    Map<LocalDateTime, Integer> calendars = holidayService.getRecentCalendar(); // 节假日日历（1次）

    for (ScheduleEventNode figureNode : figureNodeList) {
        List<ScheduleEdgeRule> ruleList = flatRules(figureNode.getEdgeInList()); // 入边规则打平（粗过滤集合）
        if (!EVENT_ENTITY.containsKey(figureNode.getName())) continue;           // 无载体概念 → 跳过
        List<Integer> entityInfo = EVENT_ENTITY.get(figureNode.getName());       // [载体类型, taskType, nodeType?]
        if (entityType == ORDER_NODE) {
            for (ScheduleOrderNode orderNode : orderNodeMap[categoryId][taskType]) {
                dealOrderNode(ruleList, orderNode, nodeTimeTrackMap, figureNode, calendars, scheduleAllNode, syncMaterialTask);
            }
        }
        if (entityType == DISPATCH_NODE) {
            for (ScheduleDispatchNode dispatchNode : dispatchNodeMap[categoryId][taskType]) {
                if (entityInfo[2].equals(dispatchNode.getNodeType())) {          // nodeType 再筛一遍
                    dealDispatchNode(...);
                }
            }
        }
    }
}
```

`flatRules`（:618）做的事：把节点所有入边的规则打平成 `List<ScheduleEdgeRule>` 副本，同时给每条规则补两个运行期字段——`codeFrom`（该入边的前置节点 uniqCode）与 `cross`（跨品类标记：规则品类 ≠ 前置节点品类）。BeanUtils 拷贝是防御性的：同一 rule 对象可能挂多条边，打平后互不污染。

**粗过滤 vs 细过滤**：doScheduleEval 阶段拿到的是「节点全部入边规则」（粗）；真正的规则筛选在 [[17.figureNode-figureCore|figureNode → filterRuleByOrderNode]]（细：品类/供应商/履约/重启/返补全匹配 + 载体自身条件）。

## 五、备注

- **同一个 figureNode 的多载体**：一个节点（如「送达及时」）下可能挂多张货单（每张一个载体实例），逐个调 dealOrderNode——一次后门重算的结果粒度是「事件×载体实例」。
- 日历只取一次（循环外），全部节点共享——四年的 {LocalDateTime→bitmask} map，内存几百 KB 级。
- 用工分支的 `nodeType` 二次过滤意味着：EVENT_ENTITY 字典里同 taskType 的多个事件（如安装的 7 个节点事件）各自只处理 nodeType 对应的载体实例——载体装载时是按 taskType 全量装的，这里按事件精筛。

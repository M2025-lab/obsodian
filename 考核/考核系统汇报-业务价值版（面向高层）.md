# 考核系统（scm-workbench）接手汇报 — 业务价值版

> 汇报对象：高层管理者
> 汇报目标：讲清系统的业务定位、产生的效益、当前所处阶段，以及我接手后的经营思路
> 整理时间：2026-10-31（综合系统代码建档与 7 月家装业务系统讨论会纪要）

---

## 一、系统定位：供应链履约时效的"自动化裁判"

在家装建材供应链中，一单材料从下单到签收要经过 **下单 → 接单 → 备货 → 测量报价 → 报价确认/审核 → 通知送货 → 送达 → 签收** 等多个环节，涉及内部采购人员、外部供应商、配送方、管家等多类角色。过去"谁慢了、慢多少、该不该罚"依赖人工统计，既滞后又有争议。

**本系统把这套裁判工作完全自动化**：每个环节的实际完成时间由履约中控（OFC）实时推送，系统按预先配置的考核规则自动判定"及时/超时"，结果直接沉淀为数据报表，并同步生成端上待办任务提醒执行人。

一句话：**它让供应链履约时效从"事后扯皮"变成"事中提醒 + 事后有据"。**

### 为什么必须有这套系统：家装履约的"期"就是钱

家装交付链路长（报价 → 选品 → 复尺 → 确品 → 下单 → 接备发 → 安装 → 验收），且**全程由工地进度驱动**——材料发早了会损坏、装早了会被后续施工破坏，发晚了工地就停工等料。**前面任何一个环节延期，后面一串环节全部受影响，时间直接等于成本。**

业务上对"期"的管理有明确诉求：**延期必须有分秒不差的线上化数据作为证据，才能支撑扣款、结算和责任认定。** 人工统计既做不到实时，也难以服众。这套系统就是全链路时效的"证据系统 + 裁判系统"——这也是它存在的根本理由。

## 二、系统覆盖的考核范围

| 维度 | 覆盖情况 |
|---|---|
| 考核指标 | 10 个核心时效指标：下单及时、接单及时、备货及时、入仓及时、测量报价及时、报价确认及时、报价审核通过及时、通知送货及时、送达及时、签收及时 |
| 考核对象 | 双向覆盖：**贝壳内部人员**（如采购下单员）+ **外部供应商/商家** |
| 规则体系 | 两级：**全国统一底线指标**（管理层定红线）+ **一城一策个性化指标**（城市按战区/大区/分公司/店铺/送货方细化，且不允许突破底线） |
| 日历能力 | 支持工作日/自然日两种口径，自动跳过节假日，考核结果公平可信 |
| 触发时效 | 事件驱动、**实时计算**（节点完成即考核），非 T+1 批处理 |

> 📌 线上量化数据待补充后引用：日均考核订单量 / 覆盖城市数 / 在库供应商数 / 日均消息处理量（可从 ES 报表与 `event_sub` 表统计）。

## 三、系统产生的四层效益

### 1. 管理效益：让供应商管理"用数据说话"
- 考核结果按供应商/城市/品类多维度沉淀，是**供应商汰换、评级、谈判的直接数据依据**。汰换场景已实现系统联动：供应商被汰换时，考核自动重算、任务自动切换，不需要人工介入。
- 延期数据线上化、可追溯，为**扣款、结算、责任认定**提供了双方认可的证据基础——把商务纠纷从"扯皮"变成"看数"。
- 底线 + 一城一策的两级体系，实现了"总部管红线、城市有弹性"的精细化治理结构——既防止城市无原则放松，也避免一刀切伤害业务。

### 2. 执行效益：从"事后罚"前移到"事中帮"
- 系统同时管理**履约任务待办卡片**：考核时间窗同步到任务上，端上用户（管家/供应商）能直接看到"还剩多久超时"，超时可以提前干预。
- 任务轴与工地进度联动：发货、安装都跟着施工阶段走，支撑**批量约货、批量安装、分批验收**——既避免材料提前进场损坏，也摊薄了监理/验收人员的上门成本。
- 工地量小的时候可以人工盯，规模上来之后只能靠系统以任务为载体管人管进度——考核系统就是这套规模化管理体系的计时中枢。

### 3. 效率效益：全自动，零人工统计
- 全链路事件驱动实时计算，替代了原本需要运营人工拉表、对时间、算时效的工作。
- 报表侧自动同步 ES / Hive / StarRocks，管理层大屏和数据团队日报直接消费，无二次加工成本。

### 4. 扩展效益：新增考核"配置化"而非"开发化"
- 指标 = 时间参考点 + 间隔 + 日历类型的公式化设计，使得**大部分考核规则调整只需运营配置，不需要排期开发**，业务响应速度从"周级发版"降到"当天生效"。

## 四、系统当前所处阶段：正在向"排程考核"演进

系统经历了三个阶段的演进，目前处于第三阶段的灰度期：

```
2.0 全国材料考核          2.5 规则重构              排程材料考核（进行中）
─────────────────  →  ─────────────────────  →  ─────────────────────────
事件节点驱动，           规则版本化管理，          与施工工期排程打通：
全国统一口径             支撑一城一策              材料送达时间跟着施工进度走，
                                                白名单项目灰度放量中
```

**排程考核的业务含义**：老模型考核"材料下单后 N 天内送达"，新模型考核"材料在该工序需要它的时间点之前送达"——考核标准从**供应链视角**升级为**施工现场视角**，直接服务于"工地不等料"这个终极目标。这是系统效益的下一个增长点。

**为什么这一步很关键**：家装履约的核心驱动逻辑是工地进度——工期环环相扣，前一道工序延期，后面安装、验收整条链都受影响。把材料考核锚定到施工排程节点上，考核体系才第一次和"交付给业主的时间"真正对齐，而不是供应链内部的自娱自乐。

**演进带来的管理成本**：新老两套模型并行期间，同一业务可能存在两条考核链路，维护成本和认知成本翻倍。**推动新老模型尽快收敛，是我接手后的重点经营方向之一。**

## 五、需要向上同步的风险与诉求

| 风险/事项 | 业务影响 | 应对 |
|---|---|---|
| **配置复杂、易配错、修数成本高**（业务侧公认痛点）：考核规则配置维度多，"很少有人能配明白"，配错后需人工修数，联动成本高 | 运营效率损耗，错配可能导致考核结果失真、影响供应商公平性 | 承接已立项方向的 **AI 三步走**：① AI 自动校验配置错误 → ② AI 受控修数替代人工 → ③ 业务人员直接与 AI 交互完成配置。这是把"痛点"变"效能产出"的机会 |
| **管理诉求多变，系统持续陪跑**：业务模式快速演变（1.0 → 2.0 → 2.5 → 排程），系统必须跟随适配 | 这是业务增长的伴生成本，不是系统缺陷；但意味着维护投入会持续存在 | 用配置化能力吸收变化（大部分规则调整已免发版）；技术侧推动模型收敛降低陪跑成本 |
| 新老模型并行，旧模型无明确下线时间表 | 双链路维护成本高，需求响应变慢，易出错 | 建议明确收敛路线图，我来牵头评估 |
| 45 个运维后门接口承担线上修数职能，缺乏审计 | 数据修改无留痕，存在合规隐患 | 计划补充操作日志与审批流程 |
| 排程考核处于白名单灰度，放量节奏依赖上游（施工排程/主材）稳定性 | 放量过快可能放大考核误差，影响供应商侧公平性 | 与上游团队建立放量前对账机制 |
| 部分批量修数操作无事务保护 | 极端情况下需人工核对补偿 | 已识别，列入短期修复计划 |

## 六、我接手后的规划

**第一个月 — 稳：**
- 完成系统全量走读（已完成：611 个类文件、32 张表、28 个接口控制器均已建档）
- 承接日常需求与线上工单闭环，保证交接期零事故
- 输出后门接口使用 SOP 与风险修复清单

**第一季度 — 顺：**
- 主导 1-2 个业务需求端到端交付，验证独立作战能力
- 推动排程考核灰度放量的数据对账机制落地
- 修复已识别的边界缺陷（时间判空、批量修数事务）

**半年 — 进：**
- 输出新老模型收敛方案，降低双链路维护成本
- 配合业务把考核数据进一步用于供应商经营（评级/汰换自动化），放大系统效益
- 承接 **AI 三步走第一步**落地：配置错误自动校验（check），再逐步开放 AI 受控修数（写），最终让业务方通过对话完成配置调整——把系统最大的运维成本项（配错 + 人工修数）转化为 AI 效能产出

Jenkins 核心概念速查表

打印出来贴在显示器旁。每课都会引用这里的词条。

本表是 jenkins-teach 课程的通用词汇表。凡是课里出现但你不熟的词，先来这里查。

角色与机器

  • Controller（控制器 / Master）：Jenkins 的"大脑"，跑 Web 界面、调度任务、管插件与凭据。它不一定要亲自干活。
  • Agent / Node（节点）：真正执行构建的机器（或容器）。可以给节点打 label（如 maven、docker）让特定任务只跑在带有该标签的机器上。
  • Executor（执行器）：节点上的一条"构建通道"，一个节点可配多个 executor，决定它能并行跑几个任务。
  • Workspace（工作区）：每次构建克隆代码、产出文件的独立目录（如 .../workspace/my-pipeline/）。不同构建默认互不干扰。

任务与运行

  • Job / Item（任务）：Jenkins 里一个可配置、可触发的东西。常见类型：Freestyle（自由风格）、Pipeline（流水线）。
  • Pipeline（流水线）：用代码（Jenkinsfile）描述的一整条交付流程，分多个 stage，可入库版本化。本课主角。
  • Build（构建 / 一次运行）：Pipeline 跑起来的一次实例，有编号 #1、#2…… 每次都有独立的日志和产出。
  • Stage（阶段）：流水线上一个"有名字的段落"，如 Build / Test / Deploy。UI 上以彩色方块展示进度。
  • Step（步骤）：stage 里的一个具体动作，如 sh 'mvn clean package'、echo 'hi'。

代码与文件

  • Jenkinsfile：放在项目根目录、入库（Git）的文本文件，是流水线的"源代码"。最佳实践：流水线定义都写在这里，而不是在 UI 里手敲。
  • Declarative Pipeline（声明式）：固定结构（pipeline { agent {…} stages {…} }），官方推荐、好读。本课只用这种。
  • Scripted Pipeline（脚本式）：基于 Groovy，更灵活但更难读。老项目兼容用。本课不展开。
  • agent：指令，告诉 Jenkins 在哪跑（any / 某 label / 某个 docker 镜像）。声明式必填。
  • SCM（源码管理）：Git/SVN 等。Jenkinsfile 通常随代码一起存在 Git 里（"Pipeline as Code"）。
  • Artifact（制品）：构建产出的可部署物，本项目中就是 release.tar.gz 或 edar-starlord-web/target/*.jar。
一句话记牢：Controller 调度 → Agent 上的 Executor 在 Workspace 里跑一个 Pipeline（由 Jenkinsfile 定义），Pipeline 分成多个 Stage，每个 Stage 里是若干 Step，最后留下 Artifact。

Jenkins 日常使用教程：建任务、配触发、看结果、排障

装好 Jenkins 之后，你每天打交道的是这些：怎么建一个任务、怎么让它自动跑、怎么读构建结果、怎么把产出留下来、跑挂了怎么定位。本课全部用你的 edar-starlord 当例子。

前两课你完成了"把构建翻译成 Jenkinsfile"和"本地跑通一次构建"。从今天起你就是 Jenkins 的长期用户了——这一课教的是日常操作面，不讲原理，讲"点哪里、看哪里、卡住看哪"。

1. 先认清两种任务（你只用 Pipeline）

一句话：你前两课建的就是 Pipeline 任务。记住一个原则——凡是能写进 Jenkinsfile 的，别在网页上手动勾。网页只用来"首次创建任务 + 指认 Jenkinsfile 在哪"。

2. 创建一个 Pipeline 任务的完整配置项

新建 New Item → 填名 → 选 Pipeline → OK 之后，页面上你真正要填的就这么几处（其余保持默认）：

  • Definition：选 Pipeline script from SCM（从 Git 读 Jenkinsfile，最规范）。只有临时试验才用 Pipeline script 直接粘脚本。
  • SCM：选 Git，填仓库 URL。
    • 远程仓库（公司 GitLab）：git@git.xxx.com:group/edar-starlord.git（需 Jenkins 配 SSH 凭据）
    • 本机同机（你现在的情况）：file:///Users/mirror/IdeaProjects/edar-starlord
  • Branches to build：填 */master 或你当前开发分支，如 */dev。
  • Script Path：填 Jenkinsfile（仓库里那个文件名，默认就在根目录）。

配完点 Save。注意：你不在网页里写构建步骤，步骤全在仓库的 Jenkinsfile 里。

3. 构建触发器：让 Jenkins 自动跑，而不是你手动点

手动点 Build Now 只是验证用。真 CI 要让它"代码一变就跑"。三种触发方式按成熟度排：

触发方式 怎么配 适合
手动
Build Now		 不用配，点就行 调试、临时跑
SCM 轮询
Poll SCM		 任务里勾 Poll SCM，填 H/5 * * * *（每5分钟看一次 Git 有没有新提交） 内网 Jenkins 连不上外网 webhook 时的折中
Webhook
（推荐）		 任务勾 GitHub hook trigger / GitLab 装插件；在 Git 仓库设置里填 Jenkins 的 webhook URL 推送即构建，最即时、最省资源
Webhook 需要 Jenkins 能被 Git 服务器访问到（公网或同内网）。你本机 127.0.0.1:8080 公司内部 GitLab 推不过来，得用 SCM 轮询或把 Jenkins 部署到能互通的机器上。

4. 参数化构建：同一个任务，传不同参数跑

比如"我想构建不同的分支"或"我想选择打测试包还是生产包"。在 Jenkinsfile 里用 parameters 块声明，网页上任务就会多一个 Build with Parameters 按钮：

pipeline {
  agent any
  parameters {
    choice(name: 'ENV', choices: ['test', 'prod'], description: '构建目标环境')
    string(name: 'BRANCH', defaultValue: 'master', description: '要构建的分支')
  }
  stages {
    stage('Build') {
      steps {
        echo "环境=${params.ENV} 分支=${params.BRANCH}"
        sh './mvnw -o clean package -Dmaven.test.skip=true'
      }
    }
  }
}

运行时点 Build with Parameters，下拉选 / 填值，再点 Build。脚本里用 params.ENV 取到你传的值。

5. 读懂构建结果：状态球、控制台、变更集

  • Console Output（每次构建点进去第一项）：排障唯一真相源。失败看最后几十行，找 ERROR / BUILD FAILURE / 红字异常。
  • Changes：这次构建包含了哪些 Git 提交（谁、改了啥）。定位"哪次提交把构建搞挂了"靠它。
  • 状态球含义：蓝/绿=成功，红=失败，黄=不稳定（编译过但测试挂），灰=还没跑/中止。

6. 把产出留下来：制品归档

构建出的 target/*.jar、release.tar.gz 默认只在 workspace 里，下次构建可能被清。要"长期可下载"就用 archiveArtifacts：

stage('Package') {
  steps {
    sh 'tar czvf release.tar.gz release'
    archiveArtifacts artifacts: 'release.tar.gz', fingerprint: true
  }
}
  • 归档后，任务首页会出现 Last Successful Artifacts，点开能下载历史任意一次成功的包。
  • fingerprint: true 让 Jenkins 记录文件哈希，能反向查"这个 jar 是哪个构建产出的"。
配合第二课的 release.tar.gz，你已经能把"编译打包好的可部署包"在 Jenkins 上点一下就下载到手——这就是最朴素的 CD 雏形。

7. 工作空间与构建历史管理

  • Workspace：~/.jenkins/workspace/<任务名>/。这是 Jenkins 每次从 Git 拉代码、跑构建、放产出的地方。出问题先来这看真实文件。
  • 清 workspace：任务页左侧 Workspace → Wipe out workspace。当"明明改了却没生效"时，先清它再构建，能排除脏缓存。
  • 删构建记录：任务页左侧 Build History 里某次构建 → Delete Build。旧构建占磁盘，可在任务配置里设 Discard old builds（保留天数/次数）自动清理。

8. 高频排障清单（贴墙级）

  • 红点 + mvnw: Permission denied：终端 chmod +x /Users/mirror/IdeaProjects/edar-starlord/mvnw。
  • 红点 + Could not find or load main class / 编译报错：看 Console 最后 30 行，多半是 pom 依赖或代码问题，不是 Jenkins 问题。
  • 任务一直排队不跑（灰）：可能没可用的 agent/executor。你本地单节点一般够用；若是分布式，检查节点是否在线。
  • 改了 Jenkinsfile 不生效：确认是改了仓库里的那份且已提交；并清一下 workspace 再构建。
  • 插件装不上（卡联网）：内网环境，找 jenkins-cli 离线装，或让我帮你出离线方案。

9. 本课小练习

练习 A（必做）：给你的 edar-build 任务加上 parameters 块（照第 4 节），用 Build with Parameters 选不同 ENV 跑一次，确认控制台打印出你传的值。
练习 B（核心）：确认构建成功后，任务首页出现 Last Successful Artifacts，点开能下载到 release.tar.gz。
练习 C（排障演练）：故意把 Jenkinsfile 里 ./mvnw 改成 ./mvnwxxx 提交，构建必红——练一次"点 Console 看错、定位、改回、重跑"的完整闭环。

10. 检索练习

凭记忆答，答完点"看答案"。

① 日常使用中，构建步骤应该写在哪里？

答案是 仓库里的 Jenkinsfile。网页只用来"创建任务 + 指认 Jenkinsfile 位置"，步骤进代码才能版本化、可 review。

② 你本机 127.0.0.1:8080 的 Jenkins，公司内部 GitLab 推送能不能直接 webhook 触发构建？

答案是 不能。回环地址只有你本机能访问，GitLab 推不过来。折中是 Poll SCM 定时拉，或把 Jenkins 放到与 GitLab 互通的环境。

③ 构建红了，第一反应该点哪里定位？

答案是 Console Output。它是排障唯一真相源，找 ERROR / BUILD FAILURE；Changes 用来辅助定位"哪次提交引入的问题"。

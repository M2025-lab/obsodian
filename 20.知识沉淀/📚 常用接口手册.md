## 1. UC ID 映射(1开头账号转3开头)— ceresManager.queryUcIdMapping

### 用途

老 UC 账号体系中 **1 开头的账号 ID** 需要转换为 **3 开头的新 ID** 时使用。通过 Ceres 服务的 ID 映射接口查询。

### 接口签名

```java
List<UcIdMappingDTO> queryUcIdMapping(List<Long> ucIds)
```

- **入参**:`List<Long>` — 待映射的 UC ID 列表(1 开头),**支持批量**
- **出参**:`List<UcIdMappingDTO>` — 映射结果列表(含 3 开头的新 ID)

### 调用示例

```java
// 1开头的账号转为3开头
UcIdMappingDTO ucIdMappingDTO = ceresManager
        .queryUcIdMapping(Collections.singletonList(Long.valueOf(param.getExecutorId())))
        .get(0);
```

场景:入参 `param.getExecutorId()` 是字符串形式的执行人 ID(1 开头),转换后取 3 开头 ID 继续后续业务。

### 注意点

| # | 注意点 | 说明 |
|---|--------|------|
| 1 | 批量接口,单查也要包成 List | 用 `Collections.singletonList(...)` 包装,结果 `.get(0)` 取回 |
| 2 | 入参必须是 `Long` | 字符串 ID 需先 `Long.valueOf(...)`,注意 NumberFormatException |
| 3 | `.get(0)` 前建议判空 | 若传入的 ID 无映射记录,返回列表可能为空,直接 `.get(0)` 会抛 IndexOutOfBoundsException |

## 2. 批量查询项目订单详情 — GET /api/order/project/details

### 用途

按项目订单号**批量查询项目订单详情**,一次最多 100 条。可选是否带出手机号。

### 接口签名

```java
@ApiOperation(value = "批量查询项目订单详情", notes = "最大支持100条")
@GetMapping({"/api/order/project/details"})
ResultDTO<List<ProjectOrderDto>> getProjectDetails(
        @RequestParam("projectOrderIds")
        @Size(min = 1, max = 100, message = "项目订单号个数需大于{min}或小于{max}")
        @NotNull(message = "项目订单号不得为空")
        Set<Long> projectOrderIds,

        @RequestParam(value = "requiredPhone", required = false, defaultValue = "true")
        Boolean requiredPhone);
```

- **入参**:
  - `projectOrderIds`:`Set<Long>` — 项目订单号集合,必填,1~100 个
  - `requiredPhone`:`Boolean` — 是否返回手机号,选填,**默认 `true`**(即默认带手机号)
- **出参**:`ResultDTO<List<ProjectOrderDto>>` — 项目订单详情列表

### 调用示例

```java
// GET 请求,集合参数以重复 query 参数形式传递:
// /api/order/project/details?projectOrderIds=1001&projectOrderIds=1002&requiredPhone=false
ResultDTO<List<ProjectOrderDto>> result =
        orderClient.getProjectDetails(Sets.newHashSet(1001L, 1002L), false);
```

### 注意点

| # | 注意点 | 说明 |
|---|--------|------|
| 1 | 批量上限 100 | 超过 100 个订单号会被 `@Size` 校验拦截,调用前自行分批 |
| 2 | `requiredPhone` 默认 `true` | 不传就会带出手机号;不需要手机号的场景**显式传 `false`**,避免多查敏感数据 |
| 3 | 入参是 `Set` 不是 `List` | 自动去重;GET 集合参数以重复 key 形式(`projectOrderIds=a&projectOrderIds=b`)传递 |
| 4 | `@Size`/`@NotNull` 直接标在 Controller 参数上 | 需类上有 `@Validated` 才会生效,详见 [[📚 批量List接口@Valid校验失效排查与解决方案]] |

## 3. 主材任务激活方法 — MaterialActivateV2Service

### 用途

starlord 中**主材任务(TaskDispatch)激活**的统一入口。把 `未激活(1)` / `暂停激活(4)` 状态的主材任务激活为 `激活未完成(2)`,并联动激活首节点、货单任务、批次、施工包。

- 接口:`com.ke.utopia.servicev2.MaterialActivateV2Service`
- 实现:`MaterialActivateV2ServiceImpl`(edar-starlord-service)

### 接口签名

按触发场景选方法:

```java
public interface MaterialActivateV2Service {

    /** 定时任务入口:批量激活满足 planActivateTime 的主材任务(分页扫全量 UN_ACTIVE) */
    void activateTaskDispatch();

    /** 按任务ID激活单个任务(仅处理 未激活/暂停激活),带尾款拦截 */
    void activateTaskDispatch(Long taskDispatchId);

    /** 通用激活入口:查配置判断是否满足激活条件 → doActivate */
    void activateTaskDispatch(TaskDispatch taskDispatch);

    /** 任务完成时,按路由配置(NMaterialRoute)激活下一个主材任务 */
    void activateNextTaskDispatch(TaskDispatch taskDispatch);

    /** 激活满足 planActivateTime 的单个任务(定时批量场景的子方法) */
    void activateTaskDispatchByPlanTime(TaskDispatch taskDispatch);

    /** 真正执行激活落库(状态更新 + 激活首节点 + 货单/批次/施工包联动) */
    void doActivateTaskDispatch(TaskDispatch taskDispatch);

    /** 检查激活前置条件 */
    TaskActivatePreConditionDTO checkPreCondition(TaskActivatePreConditionParam param);
}
```

### 调用示例

```java
@Resource
private MaterialActivateV2Service materialActivateV2Service;

// 场景1:任务完成后激活下一个任务(路由驱动)
materialActivateV2Service.activateNextTaskDispatch(taskDispatch);

// 场景2:补偿/手动激活指定任务
materialActivateV2Service.activateTaskDispatch(taskDispatchId);

// 场景3:定时批量激活到点任务(通常由 Job 调,无需业务方调)
materialActivateV2Service.activateTaskDispatch();
```

**激活链路**:

```text
activateTaskDispatch(入口,查配置/条件校验/尾款拦截)
    └→ doActivateTaskDispatch
         ├─ 更新 TaskDispatch: processStatus 1/4 → 2(激活未完成),记录 currentNodeTime
         ├─ activateTaskDispatchNode: 激活当前节点类型的第一个未激活节点
         ├─ 排程模式 && 非家装任务 → 异步(ORDER_ACTIVATE_EXECUTOR)调 workbenchManager.activeTask 激活货单任务
         ├─ materialBatchV2Service.doActivateTaskBatch: 激活批次
         └─ 安装任务(INSTALL) → handleInstallTaskAfterActivate:
              校验送货约工已完成 → 激活施工包(cube activatePackageDirect) → 触发完成约工(appointSubmit)
```

### 手动激活接口(BackDoorController)

线上补偿/手动激活单个任务,有两个 GET 后门接口,**区别在于是否走激活条件校验**:

```java
// ① 强制直接激活:查 状态1/4 且有效的任务 → 直接 doActivateTaskDispatch
//    ⚠️ 跳过激活条件校验 + 跳过尾款拦截,慎用
GET /backdoor/activateTaskDispatchDirect?taskDispatchId={id}

// ② 常规激活:查有效任务(不限当前状态) → 走通用入口 activateTaskDispatch(TaskDispatch)
//    含条件校验 + 尾款拦截,条件不满足会静默返回
GET /backdoor/activateTaskDispatchByTaskId?taskId={id}
```

| 接口 | 底层调用 | 条件校验 | 尾款拦截 | 适用场景 |
|------|---------|---------|---------|---------|
| `activateTaskDispatchDirect` | `doActivateTaskDispatch` | ❌ 跳过 | ❌ 跳过 | 明确知道该激活、条件校验误拦时的强制补偿 |
| `activateTaskDispatchByTaskId` | `activateTaskDispatch(TaskDispatch)` | ✅ | ✅ | 常规手动触发,等价于系统自然激活 |

> 两个接口的参数传的都是 **TaskDispatch 主键 id**(`taskId` 只是参数名)。查不到任务时都是**静默返回成功**,不报错,验证是否激活成功要再查任务状态。

### 注意点

| # | 注意点 | 说明 |
|---|--------|------|
| 1 | 幂等保护 | `doActivateTaskDispatch` 只处理状态 `1-未激活`/`4-暂停激活`,且 update 带原状态条件(乐观锁式),重复调用安全 |
| 2 | 尾款拦截 | 非排程模式激活前走 `checkInterceptConfigure`,尾款未付清不激活,只更新任务 |
| 3 | 材料排程模式条件不同 | `ModeEnum.isDelivery_Flow_MODE` 的任务用 `getLatestConditionList` 取**最新模板激活条件**;订单阶段不满足时置为 `暂停激活(4)` 而不是直接返回 |
| 4 | 返补任务直接激活 | 排程材料 + `FlowTypeEnum.REVERSE_ORDER` 跳过条件校验,直接 `doActivate` |
| 5 | 事务自调用 | 批量入口内用 `AopContext.currentProxy()` 调用 `activateTaskDispatchByPlanTime`,保证 `@Transactional` 生效——自己加类似逻辑时别直接 `this.` 调 |
| 6 | 独立线程池 | 货单激活走 `ORDER_ACTIVATE_EXECUTOR`(core 50/max 100/队列 200,CallerRunsPolicy),失败不影响主任务激活,但要注意队列打满时退化为主线程执行 |
| 7 | 任务状态枚举 | `1-未激活 2-激活未完成 3-激活已完成 4-暂停激活`(见 TaskDispatchStatusEnum) |

## 4. 通过施工包查货单 — GET /package/construction/query-order-nos-by-packageCode

### 用途

StarLord 中按**施工包编码(packageCode)查询其关联的货单号列表**时使用。接口由 utopia-cube 提供,StarLord 通过 Feign(`PackageQueryFeignService`)调用,并在 `PackageConstructionManager.queryOrderNosByPackageCode` 做了封装。

### 接口签名

```java
// utopia-cube-api: com.ke.utopia.cube.api.v2.pc.PackageQueryFeignService
@ApiModelProperty("通过施工包查货单")
@Deprecated
@GetMapping("/package/construction/query-order-nos-by-packageCode")
ResultDTO<List<String>> queryOrderNosByPackageCode(@RequestParam("packageCode") String packageCode);
```

- **入参**:`packageCode` — 施工包编码(query 参数)
- **出参**:`ResultDTO<List<String>>` — data 为施工包关联的**货单号(orderNo)去重列表**

服务端实现(utopia-cube `PackageQueryFeignServiceImpl`)查两张表合并:

| 表 | 条件 |
|---|---|
| `NewMaterialDemand`(新表) | packageCode + 状态 VALID |
| `PackageMaterialOrderRelation`(老表) | packageCode |

两边的 orderNo 放入 `Set` 去重后返回。

### 调用示例

```java
// StarLord 侧封装(edar-starlord-manager),直接用这个,不要裸调 Feign
List<String> packageOrderNos = packageConstructionManager.queryOrderNosByPackageCode(packageCode);
```

Manager 层行为:Feign 调用异常或 `resultDTO == null / !isSuccess()` 时抛 `UtopiaBussinessException(ERROR_INVOKE)`;否则直接返回 `resultDTO.getData()`。

### 注意点

| # | 注意点 | 说明 |
|---|--------|------|
| 1 | 接口已 `@Deprecated` | Feign 定义上标了废弃,新代码接入前先确认是否有替代接口 |
| 2 | **data 可能为 null** | 查不到任何货单时返回 `success()` 但 data 是 null(**不是空列表**),调用方必须判空 |
| 3 | packageCode 为空返回"非成功" | 入参 blank 时服务端返回裸 `new ResultDTO<>()`(无 success 标记),Manager 层会转成 `ERROR_INVOKE` 异常 |
| 4 | 顺序不保证 | 底层用 `HashSet` 去重,返回的货单号列表无排序语义 |

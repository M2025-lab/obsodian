## 0. 这个模板要解决什么

**一句话**：散文把「**可验证的状态**」写成了「**意图描述**」。

凡是能用「某个字段等于某个值 / 某段代码在某行之后 / 某次调用返回几条结果」表述的，散文都表达不了 —— 本次 r1 的 8 个功能性错误，全部可归到这 6 类：

|   |   |   |
|---|---|---|
|类别|r1 的具体表现|散文里怎么写的|
|① 判定顺序与短路语义|开关语义写成 AND（`nationEnable` 仍查白名单）|"满足「零售&&全国&&指定分公司」进入排程"|
|② 契约常量|Apollo key 后缀写错（`.company.list` ≠ `.companyList`）→ 开关恒 false|只给了个"看起来对"的 key|
|③ 落点锚点|灰度块插在方法开头 → `productComboId` 没被清空|只说"在 `X#method` 做灰度"|
|④ 多段拼接的合成方式|B 入口"两段"变一段，`[1,12]` 只返回 1 条|只说"分成两段做"|
|⑤ 入参对象的收敛状态|原参数直接进新逻辑，非 12 类型被带进去|只说"把 12 单独拎出来"|
|⑥ 范围边界|漏 3 个文件、越界改 1 个文件|没给改动清单，也没给"不要动"清单|

## 5. 一页版操作步骤

1. 通读需求，把所有 **`又…又…` / `满足…就…` / `分成两段`** 的句子挑出来 → 改写成 **§1-第 3 / 4 节判定表与决策表**（顺序 + 终止 + 子行 + 收尾 + 算例 + 负例）。

2. 把所有**外部依赖的字面量**（配置 key、接口路径、注解、方法签名、字段名）挑出来 → **§1-第 2 节契约常量表**，并写"必须一字不差"；用 `git grep` 逐个校对。

3. 每条改动都补 **§1-第 5 节的「落点锚点」+「不这么做的后果」**；锚点只写相对参照物，不写行号。

4. 兜底 / 告警 / 边界（空、null、单值）→ **§1-第 6 节**，且一律打「**【必须新增】**」或「**既有行为**」标签。

5. 用 `git diff BASE REF` 核对范围 → 写 **§1-第 0 节范围表** 与 **§1-第 8 节负向清单**。

6. 把"保持完全兼容"这类总原则拆成 **§1-第 7 节硬约束编号条目**。

7. 补 **§1-第 9 节验收命令**。

8. 用 **§2 W1–W12** 自检，再用 **§3 A1–A14** 做交付前验收；A/B 实验另需确认 W12 对等性。
